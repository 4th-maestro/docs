# 이 설계서의 전제 {.front}

- **[과제]**

  해커톤 과제 4(ES 클라우드)를 기준으로 설계했습니다. 문제는 "건물 운영자는 공간 현황과 설비 상태를 직관적으로 파악하기 어렵다"입니다.

⇒ 과제의 기본 3단계와 고급 3단계를 모두 설계하고, 고장 탐지는 "경계 확장" 모듈로 더했습니다.

- **[데이터]**

  부산대 건물 1개의 도면을 요청 중입니다. 확보 전에는 buildingSMART 커뮤니티 공개 IFC(의원 건물)로 진행합니다.

⇒ 실내기 상태와 전력 사용량은 가상 데이터이며, 화면과 발표에 가상임을 표시합니다.

- **[제어]**

  자연어 제어 명령은 스케줄 저장과 시뮬레이션까지만 수행합니다.

⇒ 실제 설비를 제어하는 인터페이스는 만들지 않습니다.

- **[확정 수준]**

  기술 스택, LLM 모델, 일정은 권장안입니다. 해커톤 종료일은 확인하지 못했습니다.

⇒ 화면 그림의 호실 번호와 수치는 설명용 예시입니다.

# 요약 {.front}

::: summary
- 고객은 건물 운영자입니다. 운영자는 도면, 설비 목록, 운전 일정을 따로 보며, 빈 공간 운전 같은 낭비를 직접 찾아야 합니다.
  - 비재실 시간 운전은 상당한 에너지 낭비 원인이며, 상업 건물 에너지의 10~30%가 비효율 운전으로 낭비된다는 추정이 있습니다(PNNL 2008).
- 서비스는 도면 한 벌로 3D 디지털트윈을 만들고, 호실 색으로 상태를 보여 주며, 운영자가 말로 묻고 스케줄을 만들고 낭비 공간을 추천받게 합니다.
  - 자연어 명령은 LLM이 도구 호출 JSON만 만들고, 서버 검증과 운영자 확인을 거쳐 시뮬레이션에만 반영합니다.
- 공개 IFC 의원 건물에서 호실 269개를 약 10초에 추출했고, 공조 단말 451개 중 448개를 좌표로 호실에 매핑했습니다.
  - 부산대 건물 도면이 확보되면 같은 스크립트로 교체합니다.

| 항목 | 값 | 기준 |
|---|---|---|
| 주 사용자 | 건물 운영자 | 과제 정의 |
| 기능 | 6단계, 요구사항 16개 | 기본 6, 고급 8, 확장 2 |
| 공개 IFC 추출 | 호실 269개, 약 10초 | 인증 샘플은 공간 2개 |
| 해석 정답률 목표 | 90%(테스트 문장 30개) | 미측정 |

# 고객과 문제

## 고객

**주 사용자는 층·호실의 냉난방을 관리하는 건물 운영자이고, 출제 기업 BECON 팀은 서비스를 제품에 확장하는 고객입니다.**

BECON은 해외 자료 기준으로 층 평면도 화면, 3D 에너지 관리 화면, 고에너지 공간 색 표시를 제공합니다. 이 서비스는 해당 화면에 필요한 공간·설비 정보를 도면에서 자동으로 만들고, 대화와 추천을 더합니다.

## 문제와 근거

**운영자는 공간과 설비를 따로 확인하고, 빈 공간 운전 같은 낭비를 직접 찾아 조치해야 합니다.**

| 문제 | 근거 | 확인 수준 |
|---|---|---|

# 해결 방법

## 서비스 한 장

**도면 한 벌로 3D 디지털트윈을 만들고, 운영자가 말로 묻고 조치하며, 낭비 공간을 추천받게 합니다.**

::: figure 서비스 개념도 | 입력, 6단계, 대화형 운영 결과
image: ../../human/explanation/img/d-s-concept.png
자료: 과제 4 구현 흐름, Maestro 팀
:::

::: table 6단계 기능
| 단계 | 기능 | 과제 구분 |
|---|---|---|
| 1 | 도면 파싱: IFC·CAD·PDF에서 층, 호실, 벽체 추출 | 기본 |
| 2 | 3D 공간 생성과 웹 뷰어: 층·호실 단위 조회 | 기본 |
| 3 | 공간-설비 매핑: 호실별 실내기 연결, 배치도 없으면 규칙 배치 | 기본 |
| 4 | 상태 시각화: On/Off, 설정온도, 사용량을 호실 색으로 표시 | 고급 |
| 5 | 자연어 질의·제어 명령: 공간 조회, 스케줄 생성(시뮬레이션) | 고급 |
| 6 | 최적 제어 추천: 가상 사용 이력으로 낭비 공간과 개선안 추천 | 고급 |
:::

## 화면

**운영자는 층 화면에서 호실 색으로 상태를 보고, 대화 패널에서 조회와 스케줄 생성을 수행합니다.**

"6층 13시 이후 미사용 회의실 냉방 OFF"를 입력하면 대상 회의실 3곳이 파란 테두리로 강조되고, 스케줄 초안이 표시됩니다.

::: figure 메인 화면 예시 | 3D 층 화면, 대화 패널, 최적 제어 추천
image: ../../human/explanation/img/d-s-mock.png
주: 호실 번호와 수치는 설명용 가상 데이터
자료: Maestro 팀
:::

## 자연어 질의

**LLM은 도구 호출 JSON만 만들고, 서버가 닫힌 값으로 검증하며, 제어 명령은 운영자 확인 후 시뮬레이션에만 반영합니다.**

::: figure 자연어 질의 처리 | 조회, 제어 명령, 해석 실패 3가지 경로
image: ../../human/explanation/img/d-s-nlflow.png
자료: Maestro 팀
:::

::: table LLM 도구 정의
| 도구 | 인자 | 동작 |
|---|---|---|
| query_spaces | 층, 용도, 지표, 정렬, 개수 | 조건에 맞는 호실 조회, 3D 강조 |
| get_status | 호실 또는 실내기 목록 | 현재 상태와 기준 시각 반환 |
| create_schedule | 대상 조건, 동작, 시각, 반복 | 초안 생성, 확인 후 저장 |
| list_schedules | 층, 날짜 | 저장된 스케줄 조회 |
| recommend | 층 또는 건물, 기간 | 낭비 순위와 개선안 반환 |
:::

## 최적 제어 추천

**가상 사용 이력에서 빈 공간 운전, 과냉·과열 설정, 업무 외 운전을 찾아 낭비 kWh 순으로 추천하고, 승인 전후를 비교합니다.**

::: figure 최적 제어 추천 | 입력, 낭비 규칙 4종, 출력과 전후 비교
image: ../../human/explanation/img/d-s-recommend.png
주: 전후 전력량은 가상 예시
자료: Maestro 팀
:::

::: table 낭비 규칙
| 규칙 | 판정 조건(기본값) | 근거 |
|---|---|---|
| 빈 공간 운전 | 예약·재실 없음 상태 30분 이상 운전 | 비재실 시간 운전 낭비(PNNL 2008) |
| 과냉·과열 설정 | 냉방 설정 26℃ 미만, 난방 설정 20℃ 초과 | 정부 권고 26℃, 공공기관 냉방 28℃ 이상(보도) |
| 업무 외 운전 | 운영 시간 밖 운전 주 2회 이상 | 과제 예시(13시 이후 미사용 회의실) |

## 차별점

**기존 3D 트윈 도구는 BIM·스캔 입력을 요구하고, 이 서비스는 IFC·PDF에서 공간-설비 화면을 자동 구성해 대화와 추천까지 연결합니다.**

::: table 기존 방식과 비교
| 비교 대상 | 기존 방식 | 이 서비스 |
|---|---|---|
| Autodesk Tandem | Revit·IFC 모델 업로드, DWG 베타(2024 포럼) | IFC 외 PDF·DXF도 입력, 호실-실내기 자동 연결 |
| Matterport | 현장 3D 스캔 | 도면만으로 생성 |
| 도면 3D 변환(어반베이스, Planner 5D) | 주거·인테리어 3D | 설비 매핑, 상태, 운영 기능 포함 |
| 운전 일정 설정 | 대상 호실·시간을 화면에서 직접 선택 | 문장 1개로 대상 판별과 스케줄 초안 생성 |
:::

## 가상 데이터

**실제 설비가 없으므로 호실 용도별 사용 패턴과 외기온도로 4주 분량의 상태·전력 시계열을 생성합니다.**

::: table 가상 데이터 생성 방법
| 데이터 | 생성 방법 | 간격 |
|---|---|---|
| 예약·재실 | 용도별 패턴(회의실 1~2시간 예약, 사무실 업무 시간) + 난수 | 이벤트 |
| 운전·모드·설정온도 | 운영 시간·예약 기반, 일부 호실에 낭비 패턴 주입 | 5분 |
| 실내온도 | 설정온도·외기온도·운전 여부로 1차 지연 모델 | 5분 |
| 전력 | 운전 시 정격 용량 × 부하율 | 5분 |
| 외기온도 | 부산 기상청 ASOS 시간별 기온 또는 합성 곡선 | 1시간 |
주: 난수 시드 고정, 낭비 패턴 주입 비율은 추천 검증용으로 기록
:::

**기능 요구사항 16개는 기본 6개, 고급 8개, 확장 2개이며, 각 요구사항에 완료 기준을 정했습니다.**

## 위험과 다음 작업

**가장 큰 위험은 부산대 도면 미제공과 LLM 오해석이며, 공개 IFC 대안과 닫힌 값 검증으로 대응합니다.**

::: table 위험과 대응
| 위험 | 영향 | 대응 |
|---|---|---|
| 부산대 도면 미제공 | 시연 건물 변경 | 공개 의원 건물 IFC로 진행 |
| PDF만 제공 | 호실 인식 오류 | 교정 화면, IFC·DXF 우선 |
| LLM 오해석 | 잘못된 호실 대상 | 닫힌 값 검증, 미리보기 확인, 되묻기 |
| 가상 데이터 신뢰도 | 추천 수치 과신 | 가상 표시, 생성 규칙 공개 |
| 실제 제어 오해 | 안전 문제 | 시뮬레이션만, 제어 인터페이스 없음 |
:::

::: table 다음 작업
| 작업 | 기한 | 담당 |
|---|---|---|
| 부산대 건물 도면 제공 여부 확인 | 미정 | 팀 전체 |
| 기술 스택 확정과 기술 선택 기록 작성 | 미정 | 팀 전체 |
| LLM 호출량·단가로 비용 점검 후 모델 결정 | 미정 | 미정 |
| 질의 테스트 문장 30개와 기대 결과 작성 | 미정 | 미정 |
| BECON 팀에 현재 화면 구성 방식과 구축 시간 확인 | 미정 | 미정 |
:::
