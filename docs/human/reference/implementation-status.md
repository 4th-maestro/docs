# 계획 대비 구현 현황

> **요약** (기준일 2026-11-21)
>
> - 중간체크 MVP 목록과 과제 4 요구 흐름 25개 항목을 점검했습니다. 가상 데이터로 정한 값(설정온도, ON/OFF, 전력, 실내온도, 습도, 재실)은 점검 대상에서 제외했습니다
> - 구현 20개, 부분 구현 4개, 미구현 1개입니다. 계획표에서 미체크였던 "특정 냉난방기 조작(스케줄 생성)"은 구현되어 있습니다
> - 부분 구현 4개는 평균 사용량 문서의 RAG 적재, 사용 빈도 측정, 기상 API 값 연결, 전력 시간대별 빈도 기반 이상 감지입니다. 미구현 1개는 가구 표시이며 의도한 제외입니다
>
> | 구분 | 항목 수 | 구현 | 부분 | 미구현 |
> |---|---|---|---|---|
> | 중간체크 MVP 목록 | 16 | 12 | 3 | 1 |
> | 과제 4 요구 흐름·주요 기능 | 9 | 8 | 1 | 0 |
> | 합계 | 25 | 20 | 4 | 1 |
>
> **다음 작업**: 기상 수집값을 대시보드 외기 온도에 연결, 전력 시간대별 빈도 이상 감지 추가 여부 결정, 가구 표시 범위 멘토 확인(5절)

점검 방법은 코드 확인, 운영 AWS 리소스 읽기 전용 조회, 이번 작업 기간의 화면·테스트 확인 기록입니다. 기능별 완료 기준은 [요구사항](requirements.md)이 원본입니다.

## 1. 점검 기준: 상태 구분과 제외 범위

**1-1. 상태는 구현, 부분, 미구현 3가지로 표시하고, 구현 방식은 모델, 규칙, 직접 구현으로 나눕니다.**

| 상태 | 기준 |
|---|---|
| 구현 | 계획 항목의 동작이 코드에 있고 화면이나 API로 동작 확인 |
| 부분 | 동작 일부만 있거나, 구현은 있으나 다른 기능과 연결되지 않음 |
| 미구현 | 코드에서 동작을 찾지 못함 |

주: 가상 데이터는 `lambda/src/sim.py`가 생성합니다. 과제 공고가 설정온도와 전력 사용량을 가상 데이터로 정했으므로 값 자체는 점검하지 않고, 값을 표시·사용하는 기능만 점검했습니다.

## 2. 중간체크 MVP 목록: 16개 중 12개 구현

**2-1. 모델, 시각화, 자연어 질의 항목은 대부분 구현되어 있고, RAG와 2차 기상 API가 부분 구현입니다.**

| 항목 | 상태 | 구현 방식 | 근거 |
|---|---|---|---|
| IFC 기반 데이터셋 | 구현 | buildingSMART 의원·복층 주택 IFC, IFC 변환기 | `lambda/ingest/ifc.py`. 의원 건축 모델 호실 269개, 문 252개 추출(로컬 0.8초) |
| 점 → 냉난방기 기호 치환 | 구현 | 직접 구현 | 인식·IFC·CAD 실내기 위치를 유형별 기호 6종으로 표시(`frontend/src/ingest/UnitSymbol.tsx`) |
| 기호 → LG 모델명과 매뉴얼 | 구현 | 표 조회 | 유형·용량별 LG 국내 모델 표와 매뉴얼 링크(`ml/hvac_types.json`), 2D 화면에서 원본 모델명·장비일람표·용량 기준 대응 |
| 미세조정 | 구현 | 모델 | YOLO11s 미세조정 v1~v7. 배포 v7 정밀도 0.660, 재현율 0.946(실제 도면 대수 기준) |
| 2D → 3D와 냉난방 정보 매핑 | 구현 | 모델·직접 구현 | PDF·이미지·IFC·DXF·DWG → 2D 실내기 매핑 → 3D 트윈(`lambda/ingest/`, `frontend/twin/pipeline/`) |
| 3D Three.js 디지털 트윈 | 구현 | 직접 구현 | `frontend/twin/digital-twin.html` |
| 가구 표시 | 미구현 | 의도한 제외 | 가구는 그리지 않고 현장 사진의 바닥·벽 마감색만 반영(`digital-twin.html` 가구 주석) |
| 매핑 정보에 따른 냉난방기 상세 | 구현 | 직접 구현 | 유형별 3D 실내기 모양·기류(`frontend/twin/pipeline/idu-shapes.js`) |
| 히트맵과 물방울 습도 | 구현 | 직접 구현 | 온도·전력·습도·쾌적도·이상 감지 5종 전환, 방 3D 물방울(습도), 단계 범례 |
| 냉난방기 ON/OFF·상태 표시 | 구현 | 직접 구현 | 3D 운전 표시, 호실 HVAC 상태 카드 |
| LLM 자연어 → 트윈 매핑 | 구현 | 모델 | Bedrock Claude Sonnet 5.5 도구 호출, 결과 호실 3D 강조(`lambda/src/query.py`, `ws.py`) |
| 의도 파악 → 역제안 | 구현 | 모델 | 답변 `action` 칸에 다음 조치 1개, 대상 불명확 시 되묻기(최근 10턴 기억) |
| 특정 냉난방기 조작(스케줄 생성) | 구현 | 모델·규칙 | 자연어 → 스케줄 초안 → 확인 후 저장 → 시뮬레이터 반영, 자동 운영 빈 방 끄기 |
| 평균 사용량 문서화 RAG | 부분 | 모델 | RAG는 규정·쾌적 기준·관련 논문 문서 7종으로 구현(`lambda/kb/`). 건물 평균 사용량 문서 적재는 없음 |
| 사용 빈도 측정 | 부분 | 직접 구현 | 전력 분석 탭 최근 4주 요일×시간 히트맵. 빈도 지표를 RAG·추천에 쓰는 처리는 없음 |
| 2차: 외부 기온·날씨 API | 부분 | 직접 구현 | 기상청 수집 스택 배포·저장 확인. 대시보드 외기 온도는 계산식이라 수집값 미연결 |

주: 특정 냉난방기 조작은 실제 설비 제어 없이 시뮬레이션으로만 동작합니다(요구사항 NFR-06).

**2-2. 기상 API는 수집까지 동작하고, 화면과 시뮬레이션에는 연결되지 않았습니다.**

- `maestro-weather` 스택이 30분마다 기상청 초단기실황을 조회해 `maestro-Weather` 테이블에 저장합니다. 2026-11-20 21:00 관측값 2.6℃(격자 98,77)를 확인했습니다.
- 운영 탭 외기 온도는 `sim.outdoor_temp`의 계산식(냉방철 27℃, 난방철 12℃ 기준 일교차)입니다.
- 트윈 운전 시뮬레이션은 저장소의 단기예보 파일(`weather.json`)을 사용합니다.

## 3. 과제 4 요구 흐름: 9개 중 8개 구현

**3-1. Expectation 1~3단계와 Advanced 4~6단계는 모두 구현되어 있고, 이상 감지 방식이 과제 설명과 다릅니다.**

| 항목 | 상태 | 구현 방식 | 근거 |
|---|---|---|---|
| 1. 도면 파싱(IFC, CAD, PDF) | 구현 | 모델·직접 구현 | IFC·DXF·DWG 변환 컨테이너, PDF는 쪽 렌더링 → 실내기 인식 모델 → 병합 |
| 2. 3D 공간 생성과 웹 뷰어 | 구현 | 직접 구현 | 층·호실 단위 3D, 층 선택과 건물 전체 보기 |
| 3. 공간-설비 매핑 | 구현 | 규칙 | 실내기 위치의 호실 포함 판정, 배치도 없는 호실은 면적 추정 실내기와 층별 실외기 자동 배치 |
| 4. 설비 상태 시각화 | 구현 | 직접 구현 | 가상 데이터를 호실 색·ON/OFF·설정온도로 표시, 5초 주기 갱신 |
| 5. 자연어 조회와 제어 명령 생성 | 구현 | 모델 | "현재 전력 사용량이 높은 공간은?" 조회, "N층 13시 이후 미사용 회의실 냉방 OFF" 스케줄 초안 |
| 6. 최적 제어 추천 | 구현 | 규칙 | 규칙 3종(빈 공간 운전, 업무 외 운전, 과냉·과열), 시뮬레이터 전후 비교 절감량(`recommend.py`) |
| 이상 감지 | 부분 | 규칙 | 설정온도 미도달(기대 온도 대비 잔차). 과제 설명의 전력 시간대별 빈도 비교 방식은 없음 |
| 실내기(IDU) 연결 | 구현 | 직접 구현 | 3D 트윈 "설비 연결" 보기, 2D 화면 실내기·실외기 연결 |
| 시연 데이터셋 | 구현 | 직접 구현 | 부산대 제6공학관 트윈 예시(`frontend/twin/source/eng6/`), 공개 IFC·PDF 샘플 등록 |

주: 운영 사이트에 등록된 건물은 2026-11-21 기준 5개이며, 모두 판매사 화면의 도면 등록(트윈 파이프라인)으로 만들었습니다.

## 4. 모델 사용 현황: 모델 6종, 규칙 3종

**4-1. 판단이 필요한 기능은 모델, 계산식으로 정할 수 있는 기능은 규칙으로 구현했습니다.**

| 기능 | 방식 | 모델·규칙 |
|---|---|---|
| 도면 실내기 기호 검출 | 모델 | YOLO11s 미세조정, SageMaker 서버리스 추론 |
| 이미지 평면도 벽·방 인식 | 모델 | CubiCasa 공개 가중치 |
| 자연어 질의, 되묻기, 역제안 | 모델 | Bedrock Claude Sonnet 5.5 |
| 규정·쾌적 기준 RAG | 모델 | Bedrock Knowledge Bases, S3 Vectors |
| 자동 운영 공실 판단 | 모델 | JEV 외부 판단 API |
| 운전 시뮬레이션 | 물리 모델 | 5R1C 즉시 계산, EnergyPlus 정밀 계산 |
| 최적 제어 추천 | 규칙 | 낭비 규칙 3종 |
| 이상 감지 | 규칙 | 기대 온도 잔차 |
| LG 모델 대응 | 규칙 | 유형·용량별 표 조회 |

주: 규칙 기반, JEV 기반, DDPG 제어 비교는 실험(`ml/hvac_control/`)이며 운영 기능에는 적용하지 않았습니다.

## 5. 남은 작업: 부분 구현 4개와 미구현 1개

**5-1. 부분 구현 항목은 연결 작업이 대부분이고, 이상 감지 방식은 추가 여부 결정이 먼저 필요합니다.**

| 작업 | 기한 | 담당 |
|---|---|---|
| 기상 수집값을 운영 탭 외기 온도와 가상 데이터 계산에 연결 | 미정 | 미정 |
| 전력 시간대별 빈도 비교 이상 감지 추가 여부 결정 | 미정 | 미정 |
| 건물 평균 사용량·사용 빈도 요약 문서를 RAG에 적재할지 결정 | 미정 | 미정 |
| 가구 표시 범위 멘토 확인(사진 기반 가구 표시 여부) | 미정 | 미정 |
| 요구사항 FR-16(BECON 읽기 인터페이스), FR-20(인원·위치 입력 최적 운전) 구현 여부 결정 | 미정 | 미정 |

주: FR-16과 FR-20은 중간체크 목록에 없어 25개 항목 집계에 넣지 않았습니다. 코드에서 두 기능을 찾지 못했습니다.
