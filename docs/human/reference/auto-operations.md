# 자동 운영 화면 규약

> **요약** (기준일 2026-11-20)
>
> - 자동 운영(빈 방 냉난방 끄기 제안·자동 조치, 이상 알림)은 AI 운영 도우미 대화 안에 AI가 보낸 알림 카드로 표시하고, 대화 마지막 상태 메시지에 ON/OFF 스위치를 배치함(2026-11-20 사용자 결정)
> - 운영 탭에서 1분마다 조회. 수락·거절·되돌리기는 모든 구성원, 스위치는 판매사 관리자와 고객사 관리자만 변경
> - 자동 운영이 저장한 끄기 스케줄은 오늘 스케줄 시간표에 "자동 운영" 라벨로 구분
>
> | 항목 | 값 |
> |---|---|
> | 조회 주기 | 60초(처리 직후 즉시 재조회) |
> | 제안 응답 기한 | 서버 기본 30분, 카드에 남은 분 표시 |
> | 스위치 변경 권한 | `admin`, `manager`(운영자는 비활성, 서버 403) |
>
> **다음 작업**: 배포 서버에서 실제 제안 데이터로 화면 확인(자동 운영 5분 스케줄은 데모 전에 켜짐, 인프라 담당)

API와 판단 규칙의 원본은 Lambda 저장소 `infra/ops/README.md`입니다. 이 문서는 화면 표시 규칙만 정합니다.

## 1. 표시 위치: AI 운영 도우미 대화

**1-1. 알림 카드는 대화 기록과 생성 시각 순으로 섞어 표시하고, 상태 메시지 카드는 항상 대화 끝에 배치합니다.**

| 요소 | 위치 | 내용 |
|---|---|---|
| 응답 대기 배지 | 대화 카드 제목 오른쪽 | `pendingCount`가 1 이상이면 "제안 N" |
| 알림 카드 | 대화 목록 안(생성 시각 순) | 상태 라벨, 시각, 서버 문구(`message`), 근거 한 줄, 3D 보기 버튼, 처리 버튼 |
| 상태 메시지 카드 | 대화 끝 | 자동 운영 ON/OFF 스위치, 안내 문구, 응답 대기 수, 마지막 변경 시각 |

주: 사용자가 대화 아래쪽(120px 이내)을 보고 있으면 새 카드가 와도 아래에 붙어 있습니다. 이전 대화를 읽는 중에는 위치를 유지합니다.

## 2. 카드 종류: 상태별 라벨과 버튼

**2-1. 상태는 왼쪽 테두리 색, 아이콘, 글자를 함께 표시합니다. 처리 기록은 흐리게 표시하고 버튼이 없습니다.**

| kind / status | 라벨 | 색 | 버튼 |
|---|---|---|---|
| `idle` / `pending` | 제안(남은 분) | 주의 | 거절, 수락 |
| `idle` / `applied` | 자동으로 끔 | 정상 | 되돌리기 |
| `idle` / `accepted` | 수락해서 끔 | 정상 | 되돌리기 |
| `anomaly` / `alert` | 이상 알림 | 위험 | 없음 |
| `rejected`, `reverted`, `expired` | 거절함, 되돌림, 만료됨 | 흐림 | 없음 |

- 근거 한 줄: AI 판단(빈 방, 사용 중, 확인 필요와 확률), 운영 종료 후 경과 분, 빈 채 운전 분, 마지막 재실 시각, 이상 알림은 현재·설정 온도입니다.
- "3D에서 호실 보기"를 누르면 3D 도면에서 해당 호실을 강조하고 선택합니다.

## 3. 처리와 오류: 즉시 반영 후 재조회

**3-1. 처리 응답을 받으면 카드를 먼저 바꾸고 목록을 다시 조회합니다. 수락과 되돌리기는 스케줄이 바뀌므로 시간표와 호실 상태도 다시 조회합니다.**

| 응답 | 화면 안내(상태 메시지 카드, 6초) |
|---|---|
| 409 | 이미 처리된 제안입니다. 목록을 다시 불러왔습니다. |
| 404 | 제안을 찾을 수 없습니다. 목록을 다시 불러왔습니다. |
| 403 | 권한이 없습니다. 자동 운영 설정은 판매사 관리자와 고객사 관리자만 바꿀 수 있습니다. |
| 403(`COMPANY_SUSPENDED`) | 기존 사용 중지 기업 화면으로 전환 |

## 4. 스케줄 시간표: 자동 운영 라벨

**4-1. `sourceText`가 "자동 운영"으로 시작하는 스케줄은 시간표 칸과 상세에 "자동 운영" 라벨(아이콘과 글자)을 표시합니다.**
