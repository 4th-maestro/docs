# AI 다중 턴 되묻기 요청 유실

> **요약** (기준일 2026-11-20)
>
> - 운영 사이트에서 "현재 재실 0곳인 곳은 HVAC 꺼줘" 요청에 AI가 시각을 2회 되물은 뒤, 3번째 턴에서 처음 요청을 잃고 층과 용도를 다시 질문함
> - 원인은 2가지. 시스템 프롬프트에 현재 시각이 없어 "지금"을 처리하지 못함. 대화 메모리가 직전 1턴만 보관해 되묻기가 2회 이어지면 처음 요청이 삭제됨
> - 프롬프트에 현재 시각을 넣고, 메모리를 최근 10턴(8KB 이하)으로 바꿔 해결. 제보 경로 다중 턴 평가 2회 모두 정답
>
> | 항목 | 수정 전 | 수정 후 |
> |---|---|---|
> | 현재 시각 전달 | 없음(추측 15:00, 되묻기, 우회 조회) | 시스템 프롬프트에 날짜·요일·시각 |
> | 메모리 보관 턴 | 직전 1턴, 1KB | 최근 10턴, 8KB |
> | 제보 경로(m01) 재현 | 2회 중 1회 제보와 동일하게 실패 | 2회 모두 마지막 턴에서 처음 요청 유지 |
> | 다중 턴 평가 5문항 | 미측정 | 2회 실행 모두 5/5 |
>
> **다음 작업**: 없음

## 1. 증상: 시각 형식 되묻기와 처음 요청 유실

**1-1. 업무동(층 1F, 2F, 3F)에서 3턴 대화 중 AI가 시각을 두 번 되묻고, 마지막 턴에서 대상 층과 용도를 다시 질문했습니다.**

| 턴 | 운영자 | AI |
|---|---|---|
| 1 | 전체 전력 추이를 확인해보고 현재 재실 0곳인 곳은 HVAC 꺼줘 | 적용 시각이 필요한데, 몇 시로 할까요? (예: 15:00, 16:00) |
| 2 | 지금 시각으로 꺼 | 적용할 시각을 HH:MM 형식으로 알려 주시겠어요? |
| 3 | 15:30 | 15:30에 끌 대상을 어느 층(1F, 2F, 3F, 전체)과 용도로 할까요? |

배경: AI에는 원문 대화 대신 대화 메모리 요약만 전달합니다([로그인과 AI 대화 메모리](../decisions/2026-11-20%28%EB%A1%9C%EA%B7%B8%EC%9D%B8%EA%B3%BC%20AI%20%EB%8C%80%ED%99%94%20%EB%A9%94%EB%AA%A8%EB%A6%AC%29.md)). 스케줄 도구의 시각 인자는 `HH:MM` 형식입니다.

## 2. 조사 과정: 같은 대화 실제 Bedrock 재현 3회

**2-1. 로컬에서 `query.run`과 `chat.make_memory`를 운영과 같은 순서로 실행해 재현했습니다.**

| 재현 | 시작 상태 | 2턴 "지금 시각으로 꺼" | 3턴 "15:30" |
|---|---|---|---|
| A | 1턴부터 실행 | 현재 시각을 "15:00으로 보고" 초안(실제 15:26) | 무엇을 할지 되묻기 |
| B | 1턴 답변이 시각 되묻기인 메모리 | 호실 조회 도구를 호출해 결과의 시각을 읽고 15:26 초안 | 무엇을 할지 되묻기 |
| C | B와 같음 | "현재 시각을 알 수 없어서… HH:MM으로" 되묻기(제보와 동일) | 층과 용도 되묻기(제보와 동일) |

**2-2. 제외한 가설은 1가지입니다.**

| 가설 | 확인 | 판단 |
|---|---|---|
| 메모리 저장 실패(DynamoDB 오류) | 재현 C는 DynamoDB 없이 메모리를 변수로 전달해도 같은 결과 | 제외 |

## 3. 원인: 현재 시각 미전달, 직전 1턴 메모리

**3-1. 시스템 프롬프트에 현재 시각이 없어, AI가 "지금"을 시각으로 바꾸지 못했습니다.**

서버는 현재 시각(`sim.now()`)을 도구 계산에만 사용했습니다. AI는 시각을 추측하거나(A), 시각이 들어 있는 도구 결과를 우회 조회하거나(B), 운영자에게 도구 인자 형식(HH:MM)을 요구했습니다(C).

**3-2. 메모리가 직전 1턴의 질문과 답변만 보관해, 되묻기가 2회 이어지면 처음 요청이 삭제됐습니다.**

| 턴 | 턴 종료 후 메모리의 질문과 답변 |
|---|---|
| 1 | 처음 요청 + "몇 시로 할까요?" |
| 2 | "지금 시각으로 꺼" + "HH:MM으로 알려 주시겠어요?"(처음 요청 삭제) |
| 3 | AI는 끌 대상을 알 수 없어 층과 용도를 되물음 |

되묻기 턴에는 초안이 없어 메모리의 초안 칸도 비었습니다. 그래서 초안이 있던 대화에서도 "15:30"을 초안 시각 수정으로 해석하지 못했습니다(재현 A, B).

## 4. 해결: 현재 시각 전달, 최근 10턴 메모리

**4-1. 사용자 결정(2026-11-20)에 따라 시각 미지정 제어 요청은 현재 시각으로 초안을 만들고, 메모리는 10턴을 보관합니다.**

| 위치 | 변경 |
|---|---|
| `lambda/src/query.py` `system()` | 현재 날짜·요일·시각 추가. "지금, 현재, 바로"와 시각 미지정 제어 요청은 현재 시각 사용, 자연어 시각("3시 반")은 HH:MM으로 변환, 운영자에게 형식 요구 금지 |
| `lambda/src/query.py` 메모리 지침 | 직전 답변이 되묻기면 짧은 응답을 처음 요청과 합쳐 처리, 초안이 있으면 짧은 응답은 초안 값 수정 |
| `lambda/src/chat.py` `make_memory` | `turns`(최근 10턴, 질문 100자·답변 150자), 상한 8KB. 되묻기 턴에도 직전 초안 유지. 이전 형식 메모리는 첫 턴으로 이어받음 |

## 5. 검증: 단위 테스트, 다중 턴 평가 2회

**5-1. 단위 테스트 2건을 추가했고, 다중 턴 평가 5문항을 2회 실행해 모두 정답이었습니다.**

- 단위 테스트: 12턴 입력 시 최근 10턴과 8KB 상한 유지, 되묻기 턴에도 초안 유지, 이전 형식 메모리 이어받기(`lambda/tests/test_chat.py`).
- 다중 턴 평가(`lambda/eval/questions.json`의 q31, m01~m04): 제보 경로(m01), 층 되묻기 후 시각 수정(m02), 초안 층 수정(m03), 자연어 시각 수정(m04), "지금" 단일 턴(q31). 2회 모두 5/5.

## 6. 교훈: 단일 턴 평가의 범위

**6-1. 단일 턴 30문항 평가는 되묻기가 이어지는 대화를 검증하지 못했습니다.**

평가 세트에 다중 턴 문항(`turns`)을 추가했습니다. 메모리나 프롬프트를 바꾸면 다중 턴 문항을 함께 실행하십시오.

## 7. 재발 시 확인 순서

1. 운영 대화 기록(`GET /chat`)에서 되묻기가 이어진 턴과 답변을 확인하십시오.
2. `lambda/tools/eval_ai.py --only m01,m02,m03,m04`로 다중 턴 문항을 실행하십시오.
3. 메모리(`mem#<사용자>#<건물>`)의 `turns`와 `draft`에 처음 요청과 초안이 남아 있는지 확인하십시오.
4. 시스템 프롬프트의 현재 시각 줄이 서울 시간인지 확인하십시오(`sim.now()`).
