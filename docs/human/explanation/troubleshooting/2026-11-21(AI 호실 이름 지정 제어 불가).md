# AI 호실 이름 지정 제어 불가

> **요약** (기준일 2026-11-21)
>
> - AI 도우미에 "1층 회의실 A, 회의실 B 13시 이후 미사용 시 냉방 OFF"를 요청하면 호실 이름으로는 대상을 고를 수 없다고 응답하고, 1층 용도 '기타' 전체 초안을 제안했음
> - 원인은 스케줄 초안 도구(`create_schedule`)의 대상 선택 인자가 층과 용도뿐인 구조. 도면으로 등록한 건물은 호실 용도가 대부분 '기타'라 이름 지정 요청을 표현할 수 없었음
> - 도구에 호실 이름 인자(`rooms`)를 추가하고, 층 미지정 되묻기 검증에서 이름 지정 요청을 제외함(Lambda #86). 초안 카드는 대상 호실 이름을 표시함(Frontend #99)
>
> | 항목(보고 건물, 1F 회의실 A·B) | 수정 전 | 수정 후 |
> |---|---|---|
> | 선택 가능한 대상 | 층, 용도('기타' 전체 5곳) | 층, 용도 또는 호실 이름(2곳) |
> | 없는 이름(회의실 C) | 해당 없음 | 후보 이름 5곳과 함께 되묻기 |
> | 초안 카드 대상 표시 | 2곳(1F, 전체 용도) | 2곳(회의실 A, 회의실 B) |
>
> **다음 작업**: 운영 AI가 `rooms`를 채우는지 같은 문장으로 확인(Lambda main `948ea9c`, 웹 main `4e756b3` 배포 2026-11-21 완료)

## 1. 증상: 이름 지정 요청의 용도 전체 제안

**1-1. 2026-11-21 사용자가 호실 이름을 지정한 제어 요청에 AI가 용도 전체 초안을 제안한 화면을 보고했습니다.**

응답은 "호실 이름으로는 대상을 고를 수 없는데, 1층 용도 '기타' 전체에 13:00 이후 미사용 시 냉방 OFF 초안을 만들까요? 선택 가능한 범위는 1F 또는 2F의 용도 '기타'입니다."였습니다(처리 2단계, 4.8초).

배경: AI 도우미는 Bedrock Claude Sonnet 5.5가 서버 도구를 호출해 답변합니다. 제어 요청은 `create_schedule` 도구가 초안을 만들고, 사용자가 화면에서 확인해야 저장됩니다.

## 2. 조사 과정: 도구 인자와 운영 호실 데이터

**2-1. 도구 정의와 운영 호실 테이블을 확인했고, 이름으로 대상을 지정하는 인자가 없었습니다.**

| 확인 | 결과 |
|---|---|
| `create_schedule` 인자(`lambda/src/tools.py`) | 층, 용도, 동작, 시각, 조건, 설정온도. 대상은 `_pick(floor, use)`로만 선택 |
| 프롬프트(`lambda/src/query.py`) | 층 목록과 용도 목록만 전달, 대상 불명확 시 후보를 들어 되묻기 |
| 운영 Rooms 테이블(읽기 전용 조회) | 보고 건물 호실 11개 중 용도 '회의실' 2곳(1F 회의실 A·B), '기타' 9곳. 다른 등록 건물 9개는 전 호실 '기타' |

| 가설 | 판단 | 근거 |
|---|---|---|
| 호실 데이터 누락 | 제외 | 1F 회의실 A·B 저장 확인 |
| 모델의 잘못된 판단 | 제외 | 도구 인자로 이름 지정을 표현할 수 없어 되묻기 규칙대로 응답 |
| 도구 대상 선택 인자 부족 | 원인 | 층, 용도 외 선택 인자 없음 |

## 3. 원인: 층·용도 전용 대상 선택

**3-1. 스케줄 초안 도구는 층과 용도 조합으로만 대상을 골랐고, 도면 등록 건물의 용도는 대부분 '기타'였습니다.**

용도가 '기타'인 건물에서는 1층 회의실 2곳만 선택할 방법이 없었습니다. 모델은 프롬프트의 "대상이 불분명하면 후보를 들어 되묻는다" 규칙에 따라 선택 가능한 범위(층, 용도 '기타')를 제안했습니다.

## 4. 해결: 호실 이름 인자와 검증 예외

**4-1. 도구는 호실 이름 배열을 받아 이름으로 대상을 고르고, 찾지 못하면 후보 이름과 함께 오류를 반환합니다.**

| 위치 | 수정 |
|---|---|
| `create_schedule` 인자 | `rooms`(호실 이름 배열) 추가. 있으면 이름 선택(`pick: rooms`, 용도 무시), 없으면 층·용도 선택(`pick: group`) |
| 이름 비교 | 공백·대소문자 무시 완전 일치(이름 또는 id) 우선, 없으면 포함 일치 1곳만 인정. 층을 말하면 그 층 안에서만 비교 |
| 찾기 실패 | 없거나 여러 곳인 이름과 후보 이름(최대 10곳)을 오류로 반환, 모델이 되물음 |
| 층 미지정 되묻기 검증 | 호실 이름을 지정한 초안은 제외. 직전 초안이 이름 선택이면 전체 범위 근거로 쓰지 않음 |
| 대화 메모리 | 이름 선택 초안의 호실 이름 보관, "15:30으로" 같은 수정에서 같은 호실 유지 |
| 초안 카드 | 이름 선택 초안은 "대상 2곳(회의실 A, 회의실 B)" 표시(3곳 초과 시 외 N곳) |

## 5. 검증: 단위 테스트, 운영 데이터, 가짜 API 화면

**5-1. Lambda 단위 테스트 229개(기존 218개, 추가 11개)가 통과했고, 운영 호실 데이터로 이름 선택을 확인했습니다.**

| 확인 | 결과 |
|---|---|
| 보고 건물 1F, "회의실 A", "회의실 B" | 1F 회의실 A, 회의실 B 2곳 선택 |
| 층 미지정, "회의실A", "회의실 b" | 같은 2곳 선택 |
| 1F, "회의실 C" | 오류, 후보 1F 호실 5곳 |
| 가짜 API 초안 카드(1440px 밝은 화면, 390px 어두운 화면) | "2곳(회의실 A, 회의실 B)", 가로 넘침 없음, 페이지 오류 0건 |

주: 실제 모델이 `rooms`를 채우는지는 배포 전에 확인하지 않았습니다(Bedrock 호출 없음).
