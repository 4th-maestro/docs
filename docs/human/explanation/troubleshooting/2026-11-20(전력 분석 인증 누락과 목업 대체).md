## 1. 증상: 새 건물만 오류

**1-1. 2026-11-20 사용자가 전력 분석 탭에서 "알 수 없는 건물: b-o92l4ace"를 보고했습니다. 건물은 13:54(UTC) 판매사 화면으로 등록됐습니다.**

배경: 전력 분석 화면은 API 요청이 실패하면 목업 값으로 대체합니다. 목업은 기존 4개 건물(본관, 업무동, 교육관, 연구동)만 압니다.

## 2. 조사 과정: 서버 직접 호출과 화면 요청 비교

**2-1. 서버 직접 호출은 모두 성공했고, 오류 문구가 화면 목업 코드에 있었습니다.**

| 확인 | 결과 |
|---|---|
| 배포 서버 전력 분석 API 10건 직접 호출(새 건물) | 9건 200, 1건 400(비교 API `period=week`, 화면은 사용 안 함) |
| 오류 문구 위치 | `frontend/src/energy/mock.ts`("알 수 없는 건물: ${id}") |
| `frontend/src/energy/api.ts` | 자체 `fetch`, `Authorization` 헤더 없음 |
| 인증 없으면 401인 가짜 API로 재현 | 요청 3건 모두 인증 없음, 같은 문구 표시 |

| 가설 | 판단 | 근거 |
|---|---|---|
| 서버 건물 캐시(60초) | 일부 원인 | 등록 직후 60초 동안 다른 실행 환경이 400을 반환할 수 있음. 30분 뒤에도 계속된 증상은 설명 못 함 |
| 화면 요청 인증 누락 | 원인 | 재현과 코드로 확인 |

## 3. 원인: 인증 없는 요청과 오류의 목업 대체

**3-1. 전력 분석 화면은 공용 요청 함수(`src/api.ts`의 `call`)가 아닌 자체 함수를 써서 로그인 필수 전환 후에도 토큰을 보내지 않았습니다.**

요청 실패를 목업으로 대체해 기존 건물에서는 오류가 드러나지 않았습니다.

## 4. 해결: 공용 요청 함수와 캐시 다시 읽기

**4-1. 전력 분석 요청을 공용 함수로 바꾸고, 목업은 API 주소가 없을 때만 사용합니다. 서버는 캐시에 없는 건물 id를 받으면 건물 목록을 한 번 다시 읽습니다(5초에 1회).**

## 5. 검증: 인증 요구 가짜 API와 단위 테스트

**5-1. 수정 후 인증 없는 요청 0건, 실제 값(합계 516kWh) 표시, 서버 400이면 서버 문구 표시를 확인했습니다. Lambda 단위 테스트 167개가 통과했습니다.**

## 6. 교훈: API 오류를 목업으로 감추지 않음

**6-1. API가 설정된 화면에서 요청 실패를 목업으로 바꾸면 인증 누락 같은 오류가 드러나지 않습니다. 목업은 API 주소가 없을 때만 사용합니다.**

## 7. 같은 증상 재발 시 확인 순서

1. 브라우저 개발자 도구에서 해당 요청의 `Authorization` 헤더와 응답 코드를 확인하십시오.
2. 화면 코드가 `src/api.ts`의 `call`을 쓰는지 확인하십시오.
3. 새 건물 등록 직후라면 서버 응답이 400인지, 다시 요청하면 200인지 확인하십시오.
