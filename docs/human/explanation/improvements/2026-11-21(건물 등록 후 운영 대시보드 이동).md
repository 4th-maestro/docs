# 건물 등록 후 운영 대시보드 이동

> **요약** (기준일 2026-11-21)
>
> - 판매사가 건물을 등록하면 기업 상세로 돌아갔음. 등록한 건물을 보려면 상단 건물 선택에서 다시 골라야 했음
> - 등록 후 새 건물의 운영 대시보드로 바로 이동하고, 앱 건물 목록 반영 전에도 "목록에 없습니다" 안내 대신 대시보드를 표시함
>
> | 항목(가짜 API, 등록 직후 첫 목록 응답은 이전 목록) | 이전 | 변경 |
> |---|---|---|
> | 등록 후 화면 | 기업 상세 | 새 건물 운영 대시보드 |
> | "목록에 없습니다" 안내(같은 주소 이동 시) | 0~4초 표시 | 표시 없음 |
> | 대시보드 지표 카드 표시 | 7.5초 | 0.5초 |
>
> **다음 작업**: 없음

## 1. 배경: 등록 후 다시 찾아야 하는 건물

**1-1. 사용자가 건물을 생성하면 바로 그 건물의 운영 대시보드로 이동하기를 요청했습니다(2026-11-21).**

등록 직후에는 앱 건물 목록이 새 건물을 아직 받지 못했을 수 있습니다. 서버 다른 실행 환경의 반영 간격은 3초이고, 앱은 등록 후 바로 1회와 4초 뒤 1회 목록을 다시 조회합니다([PDF 등록 건물 목록 누락](../troubleshooting/2026-11-21%28PDF%20%EB%93%B1%EB%A1%9D%20%EA%B1%B4%EB%AC%BC%20%EB%AA%A9%EB%A1%9D%20%EB%88%84%EB%9D%BD%29.md)).

## 2. 변경: 등록 이벤트에 건물 id 전달

**2-1. 등록 화면은 새 건물 id를 담은 변경 이벤트(`buildingCreated`)를 보내고 `#/b/<건물 id>`로 이동합니다. 앱은 그 건물이 목록에 나타날 때까지 대시보드를 그대로 표시합니다.**

도면 교체는 기존처럼 기업 상세로 돌아갑니다. 등록하지 않은 없는 건물 주소는 기존처럼 "목록에 없습니다" 안내를 표시합니다.

## 3. 검증: 등록 후 7초 측정

**3-1. 가짜 API에서 등록 직후 첫 목록 응답을 이전 목록으로 두고 0.5초 간격으로 7초 측정했습니다.**

수정 후에는 0.5초부터 지표 카드가 표시되었고, 건물 선택 이름은 0초에 건물 id, 4초부터 새 건물 이름이었습니다. 수정 전 빌드에서 같은 주소로 이동하면 0~4초 동안 "목록에 없습니다" 안내가 표시되었습니다. 운영 사이트의 실제 등록 흐름은 배포 후 확인합니다.
