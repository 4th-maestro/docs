# 개선 기록

> **요약** (기준일 2026-11-20)
>
> - 기존 화면, 성능, AI 답변 품질, 배포·운영 절차를 개선한 작업을 항목별 파일로 기록함. 수정 전후 수치와 확인 방법을 함께 남김
> - 기술 선택 기록(`decisions/`)과 장애 기록(`troubleshooting/`)이 있는 항목은 요약과 링크로 연결하고 내용을 복사하지 않음
> - 2026-11-20 기준 16건(사용자 지시로 같은 날 작업분부터 기록 시작)
>
> **다음 작업**: 없음

## 1. 기록 대상: 사용자에게 보이는 차이가 있는 개선

**1-1. 화면 배치·표시 방식, 로딩 속도·전송 크기, AI 답변 품질, 배포·운영 절차를 바꾼 작업을 기록합니다.**

| 대상 | 예 |
|---|---|
| 화면 개선 | 카드 배치 변경, 모달 전환, 디자인 통일 |
| 성능 개선 | 로딩 시간, 전송 크기, 불필요한 요청 제거 |
| 품질 개선 | AI 답변 길이, 정답 수, 평가 항목 |
| 절차 개선 | 배포 명령 확인 단계, 환경 변수 문서화 |

주: 장애 수정은 [장애 조사 기록](../troubleshooting/README.md), 여러 방법 비교는 [기술 선택 기록](../decisions/README.md)에 먼저 작성합니다. 개선 효과가 있으면 이 폴더에 요약 파일을 추가하고 원본으로 연결합니다.

## 2. 작성 방법: 파일 1개에 개선 1건

**2-1. 개선 작업과 같은 작업에서 `YYYY-MM-DD(제목).md` 파일을 추가하고 아래 목록에 한 줄을 추가하십시오.**

- 제목은 명사형입니다. 날짜는 개선을 반영한 날입니다.
- 구성은 요약(수정 전후 비교 표 포함), `1. 배경`, `2. 변경`, `3. 검증`, `관련 자료`입니다. 형식은 [문서 작성 안내](../../how-to/write-docs.md) 1절입니다.
- 수치에는 측정 조건과 수정 전 값을 붙이십시오. 측정하지 않은 항목은 미확인으로 적으십시오.
- 같은 영역을 다시 개선하면 새 파일을 추가하고 이전 파일의 관련 자료에 링크를 추가하십시오.
