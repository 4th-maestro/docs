# 트윈 로딩 화면 고정과 전송 크기 축소

> **요약** (기준일 2026-11-20)
>
> - 로딩 중 트윈 자체 화면이 보이고 시뮬레이션 입력·층 카드 값이 바뀌던 문제를, 첫 표시부터 임베드 모드와 데이터 수신 후 보고로 개선함(Frontend #33, Lambda #51)
> - CloudFront 압축과 캐시 헤더를 적용하고, 트윈 도면이 없는 건물은 트윈 화면을 불러오지 않음. 운영 배포 완료(2026-11-20)
>
> | 항목 | 수정 전 | 수정 후 |
> |---|---|---|
> | 트윈 자체 화면 노출(0.1초 간격 8초) | 14회 | 0회 |
> | 시뮬레이션 입력·층 카드 값 바뀜 | 1회, 2회 | 0회, 0회 |
> | 준비 시각(새 건물, 본관) | 1.8초, 1.1초 | 1.4초, 0.7초 |
> | 앱 JS 전송량(운영 사이트) | 451KB(압축 없음) | 133KB(brotli) |
> | 본관 트윈 화면 요청 | 18건, 309KB | 0건 |
>
> **다음 작업**: 실제 로그인 화면에서 체감 속도 확인

## 1. 배경: 앱 데이터 전 자체 화면 표시

**1-1. 사용자가 이전 버전 화면 노출, 시뮬레이션 드롭다운 바뀜, 로딩 지연을 보고했습니다.**

원인과 조사 과정은 [트윈 로딩 중 이전 화면 노출과 지연](../troubleshooting/2026-11-20%28%ED%8A%B8%EC%9C%88%20%EB%A1%9C%EB%94%A9%20%EC%A4%91%20%EC%9D%B4%EC%A0%84%20%ED%99%94%EB%A9%B4%20%EB%85%B8%EC%B6%9C%EA%B3%BC%20%EC%A7%80%EC%97%B0%29.md)입니다.

## 2. 변경: 표시 순서, 자리 표시, 전송

**2-1. 트윈·앱·서버·배포를 함께 바꿨습니다.**

| 위치 | 변경 |
|---|---|
| 트윈 | 주소 `host=1`로 첫 표시부터 임베드 모드, 앱 데이터 반영 후 보고, 데이터 파일 동시 조회 |
| 앱 | 지표 4칸·도구 줄 5칸·층 목록 자리 표시, 트윈 준비 신호 때 재전송, 트윈 도면 미리 조회 |
| 서버 | 건물 목록 `hasTwin` |
| 배포 | CloudFront `Compress: true`, `assets/*` 1년 `immutable`, 그 밖 `no-cache` |

## 3. 검증: 수정 전후 측정과 배포 서버 헤더

**3-1. 같은 조건(지연 80ms, 10Mbps, API 300ms)으로 수정 전후를 측정하고, 배포 후 응답 헤더를 확인했습니다.**

배포 서버 응답은 `Content-Encoding: br`, 해시 파일 `Cache-Control: public, max-age=31536000, immutable`, 그 밖 `no-cache`였습니다. 건물 목록은 새 건물만 `hasTwin` true였습니다.
