# 3D 트윈 만들기 진행률 막대

> **요약** (기준일 2026-11-21)
>
> - 3D 트윈을 만드는 두 과정(도면 파일 서버 변환, 평면도 이미지 3D 트윈 만들기)에 진행 정도를 알 수 있는 막대가 없었음. 서버 변환은 단계 목록, 이미지 과정은 상태 문구만 표시했음
> - 두 과정에 진행률 막대를 추가함. 단계별 예상 시간(CloudWatch 실측) 합 기준이고 진행 중 단계는 경과 시간으로 채우며 남은 시간 추정을 표시함
>
> | 항목 | 이전 | 변경 |
> |---|---|---|
> | 서버 변환(IFC 21초, PDF 3쪽 73초 실측) | 단계 목록과 아이콘 | 막대, 백분율, 현재 단계, 남은 시간 |
> | 3D 트윈 만들기(이미지) | 상태 문구 | 상태 문구 아래 막대, 백분율, 남은 시간 |
> | 예상보다 오래 걸릴 때 | 표시 없음 | 예상의 1.5배+3초 초과 시 "예상보다 오래 걸리고 있습니다" |
> | 실패 | 단계 목록 실패 아이콘 | 빨간 막대와 "단계 실패" |
>
> **다음 작업**: 배포 후 운영 변환 시간과 추정 비교, 차이가 크면 예상 시간 조정

## 1. 배경: 진행 정도를 모르는 대기

**1-1. 사용자가 3D 트윈을 만들 때 진행 막대를 요청했습니다(2026-11-21). 적용 범위는 두 과정 모두, 계산 방식은 단계와 경과 시간 추정으로 정했습니다.**

서버 변환 작업은 진행 중 단계 이름(parse, detect, merge)만 보내고 진행률은 보내지 않습니다. 실제 진행률을 받으려면 변환 컨테이너 수정과 재배포가 필요해 화면 추정 방식을 선택했습니다.

## 2. 변경: 예상 시간 기준 진행률

**2-1. 진행률은 완료한 단계의 예상 시간 합과 진행 중 단계의 경과 시간으로 계산하고, 완료 전에는 97%에서 멈춥니다.**

| 과정 | 단계와 예상 시간(초) | 근거 |
|---|---|---|
| 서버 변환 | 업로드(초당 4MB), 해석 IFC 16·CAD 12·PDF 12, 인식 IFC·CAD 2·PDF 44(2쪽), 병합 3~5 | CloudWatch 최근 3일: IngestFunction 상위 10% 16.4초(48건), DetectFunction 쪽당 중앙값 21.9초(74건) |
| 3D 트윈 만들기 | 층마다 읽기 2, 윤곽 1, 실내 공간 2, 실내기 기호 인식 30(대시보드 안), 층 맞춤·색상·지붕·마무리 1~2 | 실내기 인식은 서버 인식 중앙값과 렌더링·조회 시간 |

주: 작업 표에는 단계별 시각 기록이 없어 단계별 실측은 함수 실행 시간으로 대체했습니다.

## 3. 검증: 가짜 API와 트윈 단독 화면

**3-1. 서버 변환은 가짜 API(해석 6초, 인식 9초, 병합 3초, 실패 경우 10초 실패)로, 3D 트윈 만들기는 트윈 단독 화면에서 춘천초 PDF 1쪽으로 확인했습니다.**

| 확인 | 결과 |
|---|---|
| 서버 변환 | 0% → 97% 단계 순서대로 증가, 인식이 예상보다 길면 지연 안내 |
| 서버 변환 실패 | 빨간 막대 77%, "실내기 인식 실패" |
| 3D 트윈 만들기 | 0% → 36% → 100% 완료(로컬 약 1초), CPU 25배 감속 시 중간 17%, 약 9초 남음 |

단독 화면은 서버 실내기 인식을 하지 않아 예상(11초)보다 빨리 끝났습니다. 운영 변환 시간과 추정의 차이는 배포 후 확인합니다.
