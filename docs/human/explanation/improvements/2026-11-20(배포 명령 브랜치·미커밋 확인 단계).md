# 배포 명령 브랜치·미커밋 확인 단계

> **요약** (기준일 2026-11-20)
>
> - 브랜치 전환 실패 뒤에도 `sam deploy`가 이어 실행되어 머지 전 코드가 약 3분 배포된 사고 이후, 배포 명령 앞에 main 확인과 미커밋 확인을 `&&`로 묶음(Lambda #15)
> - 웹 배포 명령에도 같은 확인을 적용함
>
> | 항목 | 이전 | 변경 |
> |---|---|---|
> | 브랜치 확인 | 없음(명령을 따로 실행) | `git switch main && git pull --ff-only` |
> | 미커밋 변경 확인 | 없음 | `test -z "$(git status --porcelain --untracked-files=no)"` |
> | 머지 전 코드 배포 | 1회(약 3분) | 0회(같은 날 이후 Lambda·웹 배포 전부) |
>
> **다음 작업**: 없음

## 1. 배경: 작업 사본 변경으로 브랜치 전환 실패

**1-1. 미커밋 변경 때문에 `git checkout main`이 실패했고, 다음 줄의 `sam deploy`가 작업 브랜치 코드로 실행됐습니다.**

변경을 커밋한 뒤 main을 다시 배포하고, 배포된 코드 패키지를 확인했습니다.

## 2. 변경: 확인을 배포 명령과 한 줄로

**2-1. `lambda/README.md`와 `frontend/README.md`의 배포 명령은 확인 단계가 실패하면 빌드 전에 멈춥니다.**

## 3. 검증: 이후 배포

**3-1. 이후 Lambda·웹 배포는 모두 이 명령으로 실행했고, 머지 전 코드 배포는 없었습니다.**

## 관련 자료

- `lambda/README.md` 배포 절, `frontend/README.md` 배포 절
