## 1. 측정: 1단계 비용 약 3.2ms, DDPG 학습 연산이 65% 차지

**1-1. 같은 VRF 5구역 모델에서 EnergyPlus 실행과 DDPG 학습 연산을 따로 측정했습니다.**

**표 1.1 로컬 측정 결과**

| 항목 | 조건 | 결과 |
|---|---|---|
| EnergyPlus 1일 에피소드 | 새 state로 5회(크기 산정, 워밍업 포함) | 0.088~0.140초, 첫 회 외 0.09초 |
| EnergyPlus 연속 실행 | 7일, 30일 각 1회 | 0.164초, 0.338초(추가 단계당 0.079ms) |
| DDPG 학습 연산 | 1스레드, 5,000단계 2회 | 1.70~1.71ms/단계 |
| DDPG 학습 연산 | 10스레드, 5,000단계 2회 | 3.58~3.60ms/단계 |
| 실제 환경 학습(`ddpg.py`) | 로컬 M4 Pro, 3,000단계 1회 | 9초, 3.0ms/단계 |
| 실제 환경 학습(`ddpg.py`) | SageMaker ml.c5.xlarge, 3,000단계 1회 | 40초, 13.3ms/단계. 과금 151초(내려받기 포함) |

주: Apple M4 Pro, Python 3.14.7, torch 2.15.0, stable-baselines3 2.9.2. DDPG는 기본값(신경망 400·300, 배치 256, 단계마다 1회 갱신)입니다. 관측 18개, 행동 5개(공간 5곳 설정온도) 더미 환경으로 학습 연산만 측정했습니다. EnergyPlus와 학습 루프를 잇는 Gymnasium 연결 비용은 측정하지 않아 20% 여유로 반영했습니다.

**1-2. 1일 에피소드(96단계) 기준 1단계 비용은 약 3.2ms입니다.**

DDPG 1.71ms와 EnergyPlus 0.94ms(1일 0.09초 ÷ 96단계)를 더하면 2.65ms입니다. 여유 20%를 더해 3.2ms로 계산했습니다. 에피소드마다 EnergyPlus를 다시 시작하지 않고 연속 실행을 1일 단위로 나누면 EnergyPlus 비용은 0.08ms로 줄어듭니다.

## 3. 추정: 학습 1회 1.5~75분, 비교 실험 18회 병렬 0.6~2.5시간

**3-1. 1단계 3.2ms에 문헌 단계 수를 곱해 학습 1회 시간을 추정했습니다.**

**표 3.1 학습 1회 추정 시간(1스레드)**

| 시나리오 | 단계 수 | 시간 |
|---|---|---|
| 짧음(LBNL) | 28,800 | 약 1.5분 |
| 중간(TC-DDPG 논문의 표준 DDPG) | 311,712 | 약 17분 |
| 김(Sinergym 논문) | 1,401,600 | 약 75분 |

**3-2. 명세의 비교 조건을 맞추려면 학습을 여러 번 실행해야 합니다.**

계절 2개(냉방, 난방), 보상 함수 패널티 계수 λ 3개, 시드 3개를 가정하면 18회입니다. 1스레드 순차 실행은 중간 시나리오 약 5.1시간, 긴 시나리오 약 22.5시간입니다. 실행마다 1스레드를 쓰므로 10개를 병렬로 실행하면 2회 반복으로 약 0.6시간, 2.5시간입니다. 측정에서 10스레드가 1스레드보다 느렸으므로 GPU나 다중 스레드 학습은 이득이 없습니다.

주: 메모리는 실행당 수백 MB로 예상하며 측정하지 않았습니다. 평가 실행(14일, 1,344단계)은 학습 없이 수 초입니다.

**3-3. SageMaker ml.c5.xlarge에서는 1단계 13.3ms로, 50만 단계 학습 1회에 약 1.9시간이 걸립니다.**

3,000단계 테스트 작업(2026-11-20) 기준입니다. 첫 1,000단계는 신경망 갱신 없는 무작위 행동이라 50만 단계 실행의 단계당 시간은 더 길 수 있습니다. 학습 단가는 서울 리전 시간당 0.23달러(AWS Pricing API, 2026-11-20 조회)이며 1회 약 0.44달러입니다. 인스턴스당 1스레드만 사용하므로 18회를 병렬로 실행하려면 작업 18개를 동시에 실행해야 합니다.

**3-4. 첫 50만 단계 작업(`hvac-ddpg-20261120-162336`, ml.c5.xlarge 8GiB)은 시작 약 1분 만에 메모리 부족으로 종료되었습니다.**

`run.simulate`가 실행마다 EnergyPlus state를 해제하지 않아 1일 실행 1회당 약 90MB가 쌓였습니다(로컬 41회 4.1GB). `delete_state`를 추가한 뒤에도 실행 1회당 약 1.0MB가 남았습니다(300회 240MB에서 546MB). 파이썬 콜백 없이 EnergyPlus만 반복해도 1회당 약 0.6MB가 남아 EnergyPlus 내부 원인으로 판단했습니다. 50만 단계는 약 5,200회 실행이라 약 5GB가 쌓이므로 기본 인스턴스를 ml.m5.xlarge(16GiB)로 바꿨습니다.

**3-5. 재실행 작업(`hvac-ddpg-20261120-162959`, ml.m5.xlarge)은 50만 단계를 3.36시간에 마쳤고, 1단계 24.2ms로 3,000단계 테스트의 1.8배였습니다.**

| 항목 | 값 |
|---|---|
| 학습 시간 | 12,108초(50만 단계, 에피소드 5,209개) |
| 과금 시간, 비용 | 12,249초, 약 0.96달러(시간당 0.283달러) |
| 1단계 시간 | 24.2ms. 3,000단계 테스트(ml.c5.xlarge) 13.3ms, 로컬 3.0ms |
| 검증 평가 | 체크포인트 20개(2.5만 단계 간격), 냉방 검증 기간 7일 |

3,000단계 테스트는 첫 1,000단계가 신경망 갱신 없는 무작위 행동이었습니다. 인스턴스 종류도 달랐습니다. 두 요인의 영향은 분리해 측정하지 않았습니다.

**표 3.2 검증 기간(2026-07-13부터 7일) 체크포인트별 결과**

| 학습 단계 | 검증 보상 | 전력량 | 재실 중 이탈 |
|---|---|---|---|
| 2.5만 | -255.1 | 603.3kWh | 2.0h |
| 5만 | -235.2 | 547.9kWh | 3.0h |
| 10만 | -208.6 | 506.8kWh | 0h |
| 20만 | -203.4 | 501.7kWh | 0.5h |
| 30만 | -201.4 | 497.5kWh | 0.25h |
| 40만(최고) | -197.5 | 491.4kWh | 0h |
| 50만 | -203.2 | 503.9kWh | 0.25h |

주: 체크포인트 20개 중 7개를 표시했습니다. 전체 값은 `ml/hvac_control/results/cooling-ddpg-2026-08-03-14d.json`의 `ddpg.curve`에 있습니다. 같은 기간 규칙 기반은 445.2kWh, JEV 2차는 292.9kWh입니다.

2.5만 단계에서 최고 체크포인트까지 검증 보상은 57.6 개선되었고, 그중 46.4(81%)가 10만 단계 이내에 나타났습니다. 학습 에피소드 보상도 10개 구간 평균이 첫 구간 -28.7에서 셋째 구간 이후 -23.9~-24.8로 유지되었습니다. 이 설정에서 냉방 학습은 10만~15만 단계에서 대부분 수렴했습니다.

**3-6. 실측 1단계 24.2ms 기준으로 비교 실험 18회 추정을 다시 계산했습니다.**

| 단계 수 | 학습 1회 | 18회 합계 | 18회 비용 |
|---|---|---|---|
| 15만(수렴 구간) | 약 1.0시간 | 약 18시간 | 약 5.1달러 |
| 50만(이번 실행) | 약 3.4시간 | 약 61시간 | 약 17달러 |

주: ml.m5.xlarge 시간당 0.283달러, 작업마다 내려받기·검증 평가 약 2분을 포함하지 않은 값입니다. 18개 작업을 동시에 실행하면 전체 소요 시간은 학습 1회 시간과 같습니다. 계정의 동시 학습 작업 한도는 확인하지 않았습니다.

## 4. 학습 환경: Sinergym 버전 불일치, 현재 하네스 연결 필요

**4-1. Sinergym v3.12.2(2026-07-21)는 EnergyPlus 26.1.0을 사용합니다. 사용자는 안 A(현재 하네스 연결)와 SageMaker 실행을 선택했습니다(2026-11-20).**

[Sinergym Dockerfile](https://github.com/ugr-sail/sinergym/blob/main/Dockerfile)의 `ENERGYPLUS_VERSION=26.1.0`과 [PyPI](https://pypi.org/project/sinergym/)의 요구 조건(Python 3.12 이상, gymnasium 1.2.0 이상, stable-baselines3 2.7.0 이상)을 원문으로 확인했습니다. 현재 비교 모델은 EnergyPlus 26.2.0, VRF 5구역 예제, 부산 기상, 공간별 사용 일정입니다. 명세의 비교 조건(같은 건물·날씨·재실 일정·초기 조건)을 지키려면 둘 중 하나가 필요합니다.

**표 4.1 학습 환경 후보**

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| A | 현재 `ml/hvac_control` 하네스를 Gymnasium 환경으로 연결 | 규칙 기반·JEV와 같은 모델·지표 재사용 | 연결 코드 작성 필요 |
| B | Sinergym + EnergyPlus 26.1.0 추가 설치, 같은 모델을 26.1로 변환 | 명세의 구현 환경과 일치 | 버전 2개 관리, Sinergym 설정 파일 작성 |
