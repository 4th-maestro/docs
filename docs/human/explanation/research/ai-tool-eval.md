[판단 특화 모델 JEV 조사](judge-model-jev.md)에서 정한 방식(도구 선택은 정답 비교)으로 실제 Bedrock 응답을 평가했습니다.

## 1. 평가 조건: 실제 Bedrock 1회 실행

**1-1. 본관(main) 기준 30문항을 Sonnet 5.5로 1회씩 실행하고, 첫 도구 호출의 이름과 정답 인자를 비교했습니다.**

| 항목 | 값 |
|---|---|
| 모델 | `global.anthropic.claude-sonnet-5-5`(bedrock-runtime) |
| 문항 | `lambda/eval/questions.json` 30개(도구별 정답 이름과 일부 인자) |
| 채점 | 도구 이름 일치 + 정답에 적은 인자 일치. 표시 방식(`view`)은 표를 요청한 문항만 비교 |
| 사용 토큰 | 입력 126,126, 출력 8,885(문항당 입력 약 4,200) |
| 응답 시간 | 문항당 1.7~8.7초, 중앙값 약 4초 |
| 실행 | `TYPESAFE_API_KEY=$(security find-generic-password -s typesafe-api-key -w) AWS_PROFILE=maestro python tools/eval_ai.py`(lambda 폴더) |
| 결과 | 1차 `lambda/eval/results-2026-11-20.json`, 2차 `lambda/eval/results-2026-11-20-jev.json` |

주: 1회 실행 결과입니다. 같은 문항을 반복 실행했을 때의 변동은 측정하지 않았습니다.

## 2. 오답: 층 미지정 제어 요청 3건

**2-1. 층을 말하지 않은 제어 요청에서 AI는 초안 대신 층을 되물었습니다.**

| 문항 | 질문 | 정답 기준 | 실제 |
|---|---|---|---|
| q22 | 진료실 설정온도 22도로 오후 3시부터 | 전체 층 진료실 초안 | 층 되묻기 |
| q24 | 대기실 아침 8시부터 켜줘 | 전체 층 대기·휴게 초안 | 층 되묻기 |
| q26 | 사무실 난방 20도로 낮춰줘 9시부터 | 전체 층 사무실 초안 | 층 되묻기 |

조회 질문(q04, q08 등)에서는 층이 없으면 전체 층으로 처리했습니다. 제어 요청에서만 되물은 이유는 시스템 프롬프트의 "대상 층이나 용도가 불분명하면 되묻는다" 지침으로 보입니다. 2026-11-20 사용자 결정으로 층 미지정 제어 요청은 되묻기를 정책으로 정했습니다. `questions.json`의 q22, q24, q26 정답을 도구 없음으로 바꿨습니다.

## 3. 답변 품질: 내부 판단 노출 1건

**3-1. q22 답변 첫 부분에 "지침상 층이 불분명하면 되물어야 합니다"처럼 운영자에게 필요 없는 내부 판단이 포함되었습니다.**

시스템 프롬프트에 "되물을 때는 판단 이유나 지침을 쓰지 말고 질문 1문장과 후보만 쓴다"를 추가했습니다(Lambda #6). 수정 후 제어 2문항과 되묻기 6문항을 다시 실행해 8/8 정답, 내부 판단 문장 0건을 확인했습니다.

| 문항 | 수정 후 답변 |
|---|---|
| q22 | 어느 층의 진료실에 적용할까요? (1F, 2F, 전체 층) |
| q28 | 3층은 이 건물에 없어서 어느 층을 말씀하시는지 확인이 필요합니다. 1F, 2F 중 어느 층의 회의실을 끌까요? |
| q29 | 이 건물(본관)에는 업무동이 없고 1F, 2F 층과 용도 5종만 있습니다. 층별 또는 용도별로 전력을 볼까요? |

주: q29는 다른 건물을 상단 건물 선택에서 바꿀 수 있다는 안내가 없습니다. 개선 여부는 미정입니다.

## 4. JEV 답변 판단: 수치 일치와 되묻기 모두 통과

**4-1. 프롬프트 수정 후 30문항을 다시 실행하고, 답변마다 JEV(`jev-1.14.0`)로 3개 항목을 판단했습니다.**

| 판단 항목 | 선택지 | 결과 |
|---|---|---|
| 수치 일치(`numbers`) | 일치, 불일치, 수치 없음 | 일치 23, 수치 없음 7, 불일치 0 |
| 되묻기 적절(`clarify`) | 적절, 누락, 불필요 | 적절 30 |
| 이해 쉬움(`clear`) | 분명, 불분명 | 분명 29, 불분명 1(q04) |

- JEV 입력: 질문, 도구 호출(이름, 인자, 모델이 받은 도구 결과), 답변. 판단 기준 원문은 `lambda/tools/eval_ai.py`의 `JEV_QUESTIONS`입니다.
- 첫 테스트에서 그래프 데이터만 넘겼을 때 q01이 불일치(0.98)로 판정됐습니다. 답변의 재실 인원이 그래프에는 없고 도구 결과에만 있었기 때문입니다. 도구 결과 전체를 넘기도록 고친 뒤 일치(0.92)로 판정됐습니다.
- 사용 토큰(Bedrock): 입력 128,855, 출력 7,750. JEV 사용량은 이번 실행에서 기록하지 않았습니다(다음 실행부터 `usage` 기록).

**4-2. 확신도 0.8 미만 12항목(11문항)을 사람이 검토한 결과, 수치 오류와 잘못된 되묻기는 없었습니다.**

| 문항 | 낮은 확신 항목 | 검토 결과 |
|---|---|---|
| q15, q16, q18 | 수치 일치 0.58~0.68 | 증감률(1.3%, 1.2%, 5.4%)과 평일 평균(약 1,350kWh)은 도구 결과에 없는 LLM 계산값. 직접 계산해 모두 맞음 |
| q02, q05 | 수치 일치 0.76 | q02의 "0.3℃ 차이"는 LLM 계산값(24.6-24.3), 맞음 |
| q20, q23, q25 | 되묻기 적절 0.48~0.79 | 조건 없는 "끄기"(q23)를 "재실 없을 때"로 처리하고 답변에 밝힘. 문제 없음 |
| q01, q04, q19 | 이해 쉬움 0.14~0.62 | q04는 호실 영문 이름 5개를 나열. 이해에는 문제 없으나 길이가 김 |

주: 증감률처럼 LLM이 계산한 값은 이번에는 모두 맞았지만, 계산 오류 가능성이 있습니다. `energy_trend` 결과에 증감률을 포함하면 LLM 계산이 필요 없습니다.

## 5. 규칙 검사: 3문장 초과 16건

**5-1. 시스템 프롬프트의 "답변은 3문장 이내" 규칙을 30문항 중 16문항(53%)이 초과했고, JEV 이해 쉬움 판단은 이 중 15건을 분명으로 판정했습니다.**

| 문장 수 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 답변 수 | 1 | 5 | 8 | 10 | 3 | 1 | 2 |

초과 답변은 대부분 마지막에 "초안은 화면에서 확인해야 저장됩니다" 안내나 다음 조치 문장이 추가된 경우입니다. 문장 수처럼 정해진 규칙은 판단 모델보다 스크립트 검사가 정확하므로 `eval_ai.py`에 문장 수 검사(`sentences`, `over3Sentences`)를 추가했습니다.

## 6. 확인하지 못한 항목

- 같은 문항 반복 실행 시 도구 선택과 JEV 판단의 변동은 측정하지 않았습니다.
- 다른 건물(업무동 3층 등)과 영어 질문은 평가하지 않았습니다.
