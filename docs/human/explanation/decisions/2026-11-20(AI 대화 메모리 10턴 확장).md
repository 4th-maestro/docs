# AI 대화 메모리 10턴 확장

> **요약** (기준일 2026-11-20)
>
> - 채택: 대화 메모리를 직전 1턴(1KB)에서 최근 10턴(8KB 이하)으로 확장함. 원문 대화를 Bedrock에 보내지 않는 원칙은 유지
> - 이유: 되묻기가 2회 이어지면 처음 요청이 삭제되는 장애([AI 다중 턴 되묻기 요청 유실](../troubleshooting/2026-11-20%28AI%20%EB%8B%A4%EC%A4%91%20%ED%84%B4%20%EB%90%98%EB%AC%BB%EA%B8%B0%20%EC%9A%94%EC%B2%AD%20%EC%9C%A0%EC%8B%A4%29.md)). 사용자가 "10턴까지 기억하도록 메모리 상한 올려"로 결정
> - 시각을 말하지 않은 제어 요청은 현재 시각으로 초안을 만듦(사용자 결정)

## 1. 배경: 되묻기 연쇄에서 처음 요청 삭제

**1-1. 운영 사이트에서 시각 되묻기가 2회 이어진 뒤 AI가 처음 요청을 잃었습니다.**

이전 메모리는 매 턴 마지막 질문과 답변으로 덮어썼습니다. 원인과 재현은 [AI 다중 턴 되묻기 요청 유실](../troubleshooting/2026-11-20%28AI%20%EB%8B%A4%EC%A4%91%20%ED%84%B4%20%EB%90%98%EB%AC%BB%EA%B8%B0%20%EC%9A%94%EC%B2%AD%20%EC%9C%A0%EC%8B%A4%29.md)에 있습니다.

## 2. 평가 대상: 다중 턴 문항 5개

**2-1. 제보 경로를 포함한 다중 턴 문항 5개를 평가 세트에 추가했습니다.**

| 문항 | 대화 | 정답(마지막 턴) |
|---|---|---|
| m01 | 전력 추이 확인 + 재실 0곳 꺼줘 → 지금 시각으로 꺼 → 15:30 | 전체 층·용도, 15:30, 재실 없을 때 끄기 |
| m02 | 회의실 냉방 꺼줘 → 2층 → 18시로 바꿔줘 | 2층 회의실 18:00 끄기 |
| m03 | 사무실 설정온도 24도로 해줘 → 1층 → 아니 2층으로 | 2층 사무실 24℃ |
| m04 | 2층 회의실 꺼줘 → 3시 반부터로 해줘 | 2층 회의실 15:30 끄기 |
| q31 | 1층 사무실 지금 꺼줘 | 1층 사무실 끄기(현재 시각) |

## 3. 측정 방법: 실제 Bedrock 2회 실행

**3-1. `lambda/tools/eval_ai.py`로 턴마다 `query.run`과 `chat.make_memory`를 이어 실행하고, 마지막 턴의 첫 도구 호출을 정답과 비교했습니다.**

모델은 `global.anthropic.claude-sonnet-5-5`, 건물은 본관입니다. 5문항 2회 실행에 Bedrock 입력 토큰은 회당 약 69,700이었습니다.

## 4. 후보: 3가지

**4-1. 사용자에게 3가지 후보를 제시했고, 사용자는 10턴 보관을 선택했습니다.**

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 대기 중 요청 칸 추가(1KB 유지) | 되묻기 연쇄에 정확히 대응, 크기 유지 | 일반 후속 질문에는 효과 없음 | 미채택 |
| 최근 3턴 요약(2KB) | 일반 후속 질문에도 대응 | 4턴 이상 연쇄에서 같은 문제 | 미채택 |
| 최근 10턴 요약(8KB) | 긴 연쇄와 후속 질문 모두 대응 | 질의당 입력 토큰 증가 | 채택(사용자 결정) |

주: 원문 대화 전체 전송은 이전 결정("history 자체를 Bedrock 채팅에 두지 말고 메모리캐시화")에 따라 후보에서 제외했습니다.

## 5. 결과: 다중 턴 5문항 2회 모두 정답

**5-1. 수정 후 다중 턴 5문항은 2회 실행 모두 5/5였습니다.**

수정 전에는 제보 경로를 1턴 되묻기 상태부터 2회 재현했고, 1회가 제보와 같은 방식으로 실패했습니다. 단일 턴 문항 결과는 [AI 운영 도우미 도구 선택 평가](../research/ai-tool-eval.md)에 있습니다.

## 6. 결정: 최근 10턴, 8KB, 초안 유지

**6-1. 메모리는 `turns`(오래된 순 최대 10개), 마지막 조건, 대상 호실, 초안, 마지막 저장 스케줄을 보관합니다.**

- 8KB 초과 시 대상 호실 목록, 오래된 턴 순으로 축소합니다. 턴당 상한을 적용한 10턴은 최대 약 7.7KB이므로 대상 호실 목록을 먼저 축소하면 10턴이 유지됩니다.
- 되묻기 턴에는 초안이 없어도 직전 초안을 유지합니다. "15:30"처럼 짧은 응답을 초안 수정으로 처리하기 위한 규칙입니다.
- 이전 형식 메모리(`lastQuestion`, `lastAnswer`)는 첫 턴으로 이어받습니다. 메모리 TTL은 24시간 그대로입니다.

## 7. 운영 시 주의: 토큰 증가 미측정

**7-1. 10턴 메모리로 증가하는 운영 입력 토큰과 비용은 측정하지 않았습니다.**

최대 8KB(한글 약 2,700자)가 질의마다 추가될 수 있습니다. 대화가 길수록 질의당 입력 토큰이 증가하므로, 운영 로그로 질의당 입력 토큰을 확인한 뒤 상한을 다시 정하십시오.
