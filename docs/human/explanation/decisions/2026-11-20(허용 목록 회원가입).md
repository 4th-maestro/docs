# 허용 목록 회원가입

> **요약** (기준일 2026-11-20)
>
> - 채택: 허용 목록(개별 이메일, @도메인)에 있는 이메일만 자체 가입, 이메일 인증 코드 확인 후 바로 사용. 비밀번호 재설정은 인증된 이메일 코드
> - 채택: 허용 목록은 앱 "사용자 관리" 화면(관리자 그룹 전용)에서 관리, DynamoDB 저장. 메일은 Cognito 기본 메일
> - 이유: 사용자 결정 4건(2026-11-20). 여러 운영자 계정을 관리자 CLI 발급 없이 만들기 위함. [로그인과 AI 대화 메모리](2026-11-20%28%EB%A1%9C%EA%B7%B8%EC%9D%B8%EA%B3%BC%20AI%20%EB%8C%80%ED%99%94%20%EB%A9%94%EB%AA%A8%EB%A6%AC%29.md)의 "관리자 발급, 자체 가입 없음"을 대체

> |---|---|---|
> | 목록 관리 | 앱 관리자 화면 + DynamoDB | SSM 파라미터(콘솔·CLI) |
> | 허용 단위 | 이메일 + @도메인 | 개별 이메일만 |
> | 가입 후 | 이메일 인증 후 바로 사용 | 관리자 승인 후 사용 |

> **다음 작업**: 첫 관리자 계정 발급과 관리자 그룹 지정, 사용자 관리 화면 실서버 확인(미정)

[시스템 설계](../architecture.md) 2절 인증 계층의 가입 방식 결정입니다.

## 1. 배경: 여러 운영자 계정

**1-1. 운영자 여러 명이 직접 가입하되, 아무나 가입해 Bedrock 비용을 쓰지 않게 해야 했습니다.**

2026-11-20 요청은 "한 이메일 말고 허용 가능한 여러 이메일을 추가하여 비밀번호 재설정, 회원가입 등 기능을 수행"하는 것입니다.

## 2. 평가 대상: 가입 통제 지점

**2-1. 가입 요청을 Cognito가 받기 전에 거부할 수 있는지를 기준으로 비교했습니다.**

Cognito 가입 전 검사(PreSignUp 트리거) Lambda는 가입 요청마다 실행되고, 예외를 던지면 계정을 만들지 않습니다.

## 3. 측정 방법: 배포 후 화면 확인

**3-1. 허용 목록이 빈 상태에서 실제 사이트로 가입과 재설정을 1회씩 시도했습니다.**

## 4. 후보: 목록 관리, 허용 단위, 승인, 메일

**4-1. 사용자 결정 4건이며, 탈락 후보의 사유는 다음과 같습니다.**

| 탈락 후보 | 사유 |
|---|---|
| SSM 파라미터 | 화면 없음, 관리자가 AWS 콘솔 권한 필요 |
| 개별 이메일만 | 회사·학교 도메인 단위 등록 불가 |
| 관리자 승인 | 허용 목록 등록이 이미 승인 역할, 단계 1개 추가 |
| Amazon SES | 발신 도메인 DNS 인증과 샌드박스 해제 필요 |

## 5. 결과: 배포 후 확인

**5-1. 허용 목록에 없는 이메일의 가입은 거부되고, 계정은 만들어지지 않았습니다.**

| 확인 | 결과 |
|---|---|
| 허용 목록 밖 이메일 가입 | 거부, 화면 문구 "가입이 허용되지 않은 이메일입니다. 관리자에게 허용 목록 등록을 요청하십시오." |
| 비밀번호 재설정 요청 | 코드 입력 화면으로 이동. 가입하지 않은 이메일도 같은 응답(계정 존재 여부 비노출) |
| 토큰 없는 `/admin/allow` | HTTP 401 |
| 사용자 풀 변경 | 교체 없이 갱신(기존 계정 유지) |

## 6. 결정: 가입 전 검사와 관리자 그룹

**6-1. 가입은 허용 목록으로, 목록 관리는 Cognito `admin` 그룹 계정만 할 수 있습니다.**

- 관리자 판정은 액세스 토큰의 `cognito:groups` 클레임입니다. 화면의 메뉴 표시는 ID 토큰 기준이며 권한 판정은 API가 합니다.
- CLI 발급 계정(`admin-create-user`)은 가입 전 검사를 건너뜁니다. 첫 관리자는 이 방식으로 만듭니다.
- 허용 목록에서 항목을 지워도 이미 가입한 계정은 유지됩니다.

## 7. 운영 시 주의: 메일 한도와 계정 정지

**7-1. Cognito 기본 메일은 하루 50통입니다. 시연 중 가입이 몰리면 코드 메일이 지연될 수 있습니다.**

- 가입한 계정의 사용 중지·삭제 기능은 화면에 없습니다. 필요하면 `aws cognito-idp admin-disable-user`를 사용하십시오.
- 허용 목록 이메일은 개인정보이므로 저장소에 기록하지 않습니다.
