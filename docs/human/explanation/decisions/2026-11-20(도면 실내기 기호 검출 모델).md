## 1. 배경: 도면의 점 표시를 실내기 기호와 LG 모델로 교체

**1-1. 2D 도면을 3D 트윈으로 바꿀 때 실내기 위치와 유형, LG 모델번호를 함께 연결해야 합니다.**

기존 도면 JSON(`frontend/public/floorplans/`)의 `hvac` 칸은 좌표 점만 있습니다. 사용자 계획은 IFC 기반 데이터를 정제해 점을 실제 HVAC 기호로 바꾸고, 기호를 LG 실내기 모델과 매뉴얼에 연결한 뒤 미세조정하는 것이었습니다. 학습은 SageMaker를 AWS CLI로 실행하는 조건입니다. 사용자는 2026-11-20에 다음과 같이 선택했습니다.

| 질문 | 선택 | 탈락한 선택지 |
|---|---|---|
| 학습 데이터 | CubiCasa5K와 기호 합성, IFC 렌더는 평가 전용 | IFC만 사용, IFC와 CubiCasa 혼합 학습 |
| 모델 범위 | YOLO 기호 검출만 학습, 벽·방은 공개 가중치 | CubiCasa 분할 모델에 실내기 클래스 추가 |
| LG 모델 연결 | 유형 분류 후 표 조회 | 모델번호 직접 분류 |
| 기호 원본 | 코드로 표준 기호 생성 | 제조사 CAD 블록 수집 |
| 학습 인스턴스 | ml.g6.xlarge | 미선택 |
| 범위 | 학습과 Model Registry 등록, Endpoint는 Step Functions 작업에서 배포 | Endpoint 즉시 배포 |

## 2. 평가 대상: 합성 테스트, IFC 렌더, 실제 설계도면

**2-1. 학습 분포 안(합성), 도면 양식 차이(IFC), 기호 양식 차이(실제 도면)를 각각 측정했습니다.**

| 평가 세트 | 구성 | 정답 |
|---|---|---|
| 합성 테스트 | CubiCasa5K test 분할 400장 | 합성 시 기록한 기호 상자 2,548개 |
| IFC 평가 | buildingSMART 의원 건물 IFC 평면 타일 32장(1m당 80px, 1400px) | 급기구 좌표에 천장형 3종 기호를 그린 라벨 233개. 환기구는 라벨 없는 방해 기호 |
| 실제 도면 | 춘천초 증축 냉난방기 설계도면(나라장터 R26BK01810384) 5쪽, 타일 102장 | 실내기 37대 중 v1 클래스에 있는 4방향 카세트 62개, 스탠드형 14개(타일 중복 포함) |

주: IFC 평가 기호는 학습과 같은 그리기 코드로 그렸습니다. 따라서 IFC 점수는 기호 양식 일반화를 측정하지 않습니다. 실제 도면 라벨은 템플릿 매칭과 확대 검수로 만들었으며 사용자 검수 전입니다.

## 3. 측정 방법: ultralytics 검증, 실행 시간 기준 비용

**3-1. 모든 점수는 ultralytics 8.4.200 `val`(이미지 1024px)의 mAP50, mAP50-95입니다.**

- 합성 테스트는 학습 작업 안에서 `best.pt`로 채점했습니다. IFC 평가와 실제 도면은 같은 가중치를 내려받아 로컬(Apple M4 Pro, MPS)에서 채점했습니다.
- 실제 도면은 350dpi로 렌더링한 뒤 1m당 80px로 축척을 맞추고, 1400px 타일(1000px 간격)로 잘랐습니다. 타일 안에 60% 이상 보이는 기호만 라벨로 유지합니다.
- 비용은 과금 시간(`BillableTimeInSeconds`) 또는 작업 시작·종료 시각에 서울 리전 시간당 단가를 곱했습니다. 단가는 AWS Pricing API로 2026-11-20에 조회했습니다.

## 4. 후보: 데이터, 모델 범위, 모델번호 연결 방식

**4-1. 공개 IFC는 실내기 기호 다양성이 부족해 학습 데이터에서 제외했습니다.**

| 후보 | 판단 | 이유 |
|---|---|---|
| IFC만 학습 | 제외 | 실내기 단말이 있는 공개 IFC는 의원 건물 1동 수준이라 도면 양식이 1종 |
| IFC와 CubiCasa 혼합 | 제외 | IFC 타일 32장은 학습 비중이 작아 평가용으로 남김 |
| CubiCasa 분할 모델 클래스 확장 | 제외 | 벽·방 분할 재학습까지 범위가 커지고, 공개 가중치로 벽·방은 해결 |
| 비전 언어 모델로 직접 좌표 출력 | 제외 | 픽셀 좌표 정밀도가 낮고 호출마다 비용 발생 |
| CubiCasa5K와 기호 합성 | 채택 | 실제 평면도 5,000장 위에 크기·위치를 통제한 라벨 생성 가능 |

**4-2. 같은 유형의 모델번호는 기호 모양이 같아 모델이 구분할 수 없으므로 표 조회로 연결합니다.**

모델은 유형만 분류하고 `ml/hvac_types.json`에서 LG 예시 모델과 매뉴얼을 찾습니다. 예시 모델은 해외 LG 자료 기준이며 국내 판매 모델명은 확인하지 못했습니다.

## 5. 결과(1): v1은 합성 분포 안에서는 과적합 없음

**5-1. 검증 손실이 60 에포크까지 계속 감소했고, 테스트 점수도 검증 점수와 차이가 0.01 이내입니다.**

## 6. 결과(2): v1은 실제 설계도면의 실내기를 거의 찾지 못함

**6-1. 실제 도면의 mAP50은 0.006으로, 합성 기호 모양에 과적합된 상태였습니다.**

| 클래스 | 실제 도면 기호 수 | 정밀도 | 재현율 | mAP50 |
|---|---|---|---|---|
| 4방향 카세트 | 62 | 0.125 | 0.032 | 0.012 |
| 스탠드형 | 14 | 0 | 0 | 0 |

실제 도면의 4방향 카세트는 굵은 이중 테두리 안을 검은 정사각형으로 채운 기호입니다. 합성 기호(사각형, 안쪽 사각형, 모서리 연결선)와 모양이 다릅니다. 3층 평면에서는 교실 카세트 6대를 모두 놓쳤습니다. 대신 계단을 1방향 카세트(신뢰도 0.55)로, 관경 표시 박스 "32"를 스탠드형(0.79)으로 잘못 검출했습니다.

**6-2. 실제 도면에는 v1 클래스에 없는 2방향 카세트가 있었습니다.**

첨부 내역서 기준 실내기는 4방향(11.0~14.5kW) 27대, 2방향(5.2~6.0kW) 6대, 스탠드형(29.0kW) 4대입니다. 2방향은 소형 실(영양사실, 휴게실, 교사연구실)에 설치됩니다.

## 7. 결과(3): 실제 도면 수집 경로

**7-1. 공개 해외 도면 10건은 대부분 덕트식이라 실내기 기호를 얻지 못했고, 국내 관급자재 공고 첨부 도면을 사용합니다.**

| 출처 | 확인 건수 | 결과 |
|---|---|---|
| 미국·캐나다 공공 발주 기계 도면 | 10건 | 덕트 급기구, VAV 위주. 벽걸이형 몇 대만 확인 |
| 나라장터 냉난방기 공고(물품 8, 공사 1) | 9건 | 공고문, 내역서, 시방서만 첨부(도면 없음) |

나라장터 첨부파일은 공고번호로 로그인 없이 내려받을 수 있습니다. 반면 열람 화면의 내부 검색 요청은 직접 호출하면 403으로 차단됩니다. 그래서 공고 검색은 공공데이터포털 공식 API(조달청 나라장터 입찰공고정보서비스)로 하기로 했습니다. 인증키는 2026-11-20에 발급받았으며, 같은 날 기준 "등록되지 않은 서비스키" 응답으로 활성화를 기다리고 있습니다.

## 8. 결정: 국내 CAD 기호 합성과 실제 도면 라벨 혼합(v2)

**8-1. 사용자는 2026-11-20에 v2 구성으로 다음 세 가지를 선택했습니다.**

| 질문 | 선택 | 탈락한 선택지 |
|---|---|---|
| 2방향 카세트 | `cassette_2way` 클래스 추가(LG ARNU12GTSC4, 유형 TS) | 1방향에 합침, 평가에서 제외 |
| 공고 검색 | 공공데이터포털 API 키 발급 | 사용자가 공고번호 전달, 춘천초 1건만 사용 |
| 재학습 | 합성 기호 다양화와 실제 라벨 혼합 | 실제 라벨로 미세조정만, 합성 기호 다양화만 |
| 실제 도면 라벨링 | Claude 라벨과 사용자 검수 | 사용자가 도구로 직접 수정, Claude 단독 |
| 실제 도면 용도 | 평가와 추가 학습 | 평가 전용 |

- `synth.py`는 도면의 50%를 국내 CAD 기호로 그립니다. 기호 주변에는 라벨 없는 연결 박스, 배관, 관경 박스, 용량 태그를 함께 그립니다. 합성 데이터 v2는 `data/hvac-yolo-v2`에 생성합니다.
- `train.py`는 실제 학습 타일을 20회 반복해 합성 데이터에 섞고, 실제 테스트 타일은 별도로 채점합니다.
- 사용자는 평가용 건물 수집과 라벨 검수를 기다리지 않고 v2 학습을 진행하도록 지시했습니다(2026-11-20). 확보한 실제 도면이 춘천초 1동이므로, 첫 v2 학습은 합성 v2만으로 하고 춘천초는 처음 보는 건물 평가에 사용합니다. 실제 라벨 혼합은 다른 건물 도면을 확보한 뒤 진행합니다.
- v1은 Model Registry `hvac-symbol-detector` 버전 1(승인 대기)로 등록했습니다. 실제 도면 점수가 기준에 못 미치므로 승인하지 않습니다.

## 9. 운영 시 주의: 라이선스, 평가 분리, 비용

**9-1. 학습 데이터와 가중치는 비상업 용도로만 사용합니다.**

- CubiCasa5K는 CC BY-NC-SA 4.0이고 ultralytics는 AGPL-3.0입니다. 서비스 배포 전에 라이선스를 검토하십시오.
- 나라장터 설계도면은 저장소에 넣지 않습니다. S3 `data/hvac-real-src/`에 보관하고 라벨(`ml/real_labels/`)에는 출처 공고번호를 기록합니다.

**9-2. 실제 도면 평가는 학습에 쓰지 않은 건물로만 합니다.**

같은 건물의 냉매배관 평면도와 제어선 평면도는 실내기 위치가 같습니다(1px 이내). 한쪽을 학습에 쓰면 다른 쪽은 평가에 쓸 수 없습니다. 실제 도면 축척은 1/200 외에 1/100 쪽도 있으므로, 라벨 파일에 쪽마다 축척을 기록하십시오.

**9-3. 합성 데이터 생성 시간 대부분은 원본 다운로드입니다.**

v1 처리 작업 46.5분 중 Zenodo 다운로드가 41.5분, 압축 해제와 합성이 1분 40초였습니다(ml.c5.4xlarge). v2 첫 실행은 다운로드가 60분 안에 끝나지 않아 최대 실행 시간 3,600초에서 중단되었습니다. Zenodo는 연결 1개당 속도를 제한합니다(로컬 측정 0.37MB/s). 그래서 `synth.py`는 구간 요청 16개로 병렬 다운로드하도록 바꿨습니다. `sagemaker.sh data`는 압축 파일(5,469,495,706바이트)을 S3 `data/src/`에 보관하고, 다음 실행부터 S3에서 읽습니다.

| 작업 | 시간 | 비용 |
|---|---|---|
| 합성 데이터 v1(처리 작업) | 46.5분 | 약 0.71달러 |
| 합성 데이터 v2 첫 실행(다운로드 중 시간 초과) | 60분 | 약 0.92달러 |
| 환경 점검 학습(1 에포크, 데이터 5%) | 340초 | 약 0.13달러 |
| v1 본 학습(60 에포크) | 6,042초 | 약 2.32달러 |

주: 실시간 Endpoint는 배포하지 않았습니다. Serverless Endpoint는 10-3절입니다. 운영 규칙은 루트 `AGENTS.md` "SageMaker Endpoint 비용 관리"입니다.

추론은 ONNX와 onnxruntime(CPU)으로 바꿔 Serverless Endpoint `hvac-symbol-detector-sls`(메모리 6,144MB, 동시 실행 2)에 배포했습니다. 전처리를 학습과 같은 OpenCV INTER_LINEAR로 맞춘 뒤에는 실제 도면 타일 6장의 결과가 ultralytics와 같았습니다. 주: 기호 모양을 춘천초 한 건물에 맞춰 조정했으므로 다른 건물에서는 낮게 나올 수 있습니다.

## 16. 결과(10): 문 클래스를 더한 v8은 실내기 정밀도가 낮아 채택하지 않음

**16-1. CubiCasa5K 문 라벨로 `door` 클래스를 더한 v8은 실내기 정밀도가 0.660에서 0.557로 낮아져 Endpoint를 v7로 유지했습니다(2026-11-21).**

| 지표(춘천초 PDF 4~8쪽, 신뢰도 0.5 이상, 문과 실내기 분리 병합) | v7 | v8 |
|---|---|---|
| 실내기 정밀도 | 0.660 | 0.557 |
| 실내기 재현율 | 0.946(37대 중 35대) | 0.919(37대 중 34대) |
| 4방향 오검출 | 6개 | 12개 |
| 문 검출 수 | 없음 | 82개(라벨 없음, 정확도 미확인) |
| 합성 테스트 문 mAP50-95 | 없음 | 0.799 |

학습 데이터의 문 라벨은 41,969개로 실내기 라벨(약 2만 4천 개)보다 많습니다. 문 학습이 실내기 판정 경계에 영향을 준 것으로 봅니다. 문 클래스 코드는 상위 저장소 브랜치 `feat/door-class`에 두고 본선에 합치지 않았습니다. 문 인식은 별도 모델로 분리하거나 문 라벨 비중을 줄여 다시 학습하는 방안을 검토합니다. IFC, CAD 문 추출과 2D 문 편집은 모델과 관계없이 배포되어 있습니다.

## 17. 결과(11): 두 번째 건물에서는 v4, v7 모두 실내기를 찾지 못함

**17-1. 다른 설계사무소 도면(인하대 송도 산학협력관 1층)의 4방향 카세트 20대를 v4, v6, v7 모두 0대 찾았습니다(2026-11-21).**

| 항목 | 값 |
|---|---|
| 도면 | 나라장터 공고 R26BK01263334 첨부 `2. 공사도면.pdf` 2쪽 지상1층 평면도(변경후), 1/500, A4(원문 S3 `data/hvac-real-src/`) |
| 라벨 | `ml/real_labels/songdo_iic.json` 4방향 카세트 20대(템플릿 매칭 점수 0.33 이상, 육안 확인, 사용자 검수 전) |
| v4, v6, v7 재현율(신뢰도 0.5 이상, 운영 경로) | 0/20, 0/20, 0/20 |
| v7 신뢰도 0.05, 기호 주변 확대 1.4~3배 | 0/20 |
| 같은 기호를 본 1개로 찾은 템플릿 매칭 | 20/20(점수 0.33 이상 후보 20개 모두 실내기, 0.33 미만 217개 중 실내기 0개) |

이 도면의 4방향 카세트 기호는 겹테두리 안에 격자(루버) 선이 있는 모양입니다. 학습한 춘천초 기호(굵은 테두리, 가운데 채움)와 그리는 방식이 다릅니다. 크기를 바꿔도 0대이므로 원인은 축척이 아니라 기호 모양입니다. 현재 모델은 학습에 반영한 기호 모양에만 동작하며, 다른 건물 일반화는 확인되지 않았습니다. 1쪽 변경전 평면도는 기호가 달라 라벨에서 제외했습니다.

**17-2. 도면마다 기호 모양이 다르므로, 도면 안 기호 1개를 본으로 지정해 같은 기호를 찾는 방식이 일반화에 유리합니다.**

설계도면은 범례에 기호를 정의하고 같은 도면 안에서는 같은 기호를 반복합니다. 이번 라벨 작업에서 본 1개로 20대를 모두 찾았습니다. 다음 방안은 2D 화면에서 운영자가 기호 1개를 지정하면 같은 쪽에서 유사 기호를 찾는 기능, 합성 데이터에 격자형 카세트 등 기호 모양 추가, 여러 건물 실제 라벨을 학습에 섞는 것입니다.

## 18. 결과(12): 여러 건물 실제 라벨로 학습한 v9가 처음 보는 건물에서 v7보다 나아 채택

**18-1. 학습용 4개 건물의 실제 타일과 기호 변형 3종을 더한 v9는 평가 전용 6개 건물 합산 재현율이 0.288에서 0.566으로, 정밀도가 0.381에서 0.632로 올라 Endpoint를 v9로 교체했습니다(2026-11-21).**

| 평가 전용 건물(신뢰도 0.5 이상, 운영 경로) | 실내기 | v7 정밀도, 재현율 | v9 정밀도, 재현율 |
|---|---|---|---|
| 춘천초(v4~v7 기호 조정에 사용) | 37 | 0.660, 0.946 | 0.540, 0.919 |
| 인하대 송도 | 20 | 0, 0 | 0.833, 1.000 |
| 천안시 자원봉사센터 | 26 | 0.441, 0.577 | 0.700, 0.808 |
| 부산 사하중 | 89 | 0, 0 | 0.407, 0.124 |
| 춘천 근화초 | 18 | 0.077, 0.056 | 0.682, 0.833 |
| 충북국제교육원 | 22 | 0.625, 0.455 | 0.792, 0.864 |
| 합계 | 212 | 0.381, 0.288(61대) | 0.632, 0.566(120대) |
| 춘천초 제외 합계 | 175 | 0.243, 0.149 | 0.677, 0.491 |

학습 데이터는 합성 4,200장과 학습용 4개 건물(한국외대, 한신대, 고려대 세종, 파주) 실제 타일 425장을 5회 반복한 것입니다. 합성 기호에는 학습용 건물에서 본 4방향 빗금형, 4방향 겹테두리형, 1방향 루버형을 더했습니다. 평가 전용 건물은 학습과 기호 조정에 쓰지 않았습니다(춘천초는 이전 버전 조정에 사용). 학습은 ml.g6e.4xlarge 약 52분, Registry 패키지 버전 7입니다. 운영 상태 머신으로 송도 도면을 변환해 2쪽 인식 20개(179초)를 확인했습니다. 수집 과정은 [실내기 도면 실제 라벨 건물 수집](../research/2026-11-21%28%EC%8B%A4%EB%82%B4%EA%B8%B0%20%EB%8F%84%EB%A9%B4%20%EC%8B%A4%EC%A0%9C%20%EB%9D%BC%EB%B2%A8%20%EA%B1%B4%EB%AC%BC%20%EC%88%98%EC%A7%91%29.md)입니다.

**18-2. 춘천초는 정밀도가 0.660에서 0.540으로 낮아졌고, 사하중은 재현율 0.124로 여전히 낮습니다.**

춘천초 하락은 4방향 오검출 28개가 원인이며, 이전 버전이 이 건물에 맞춰져 있었던 효과가 줄어든 것으로 봅니다. 사하중은 기존 4방향(X 표시 사각형), 신설 4방향(검은 정사각형), 회전된 동이 섞여 있어 학습 건물에 없는 기호 계열입니다. 남은 오검출과 미검출은 2D 화면의 기호로 찾기(규약 3-6절)로 보완합니다.
