# AWS 아키텍처와 기술 스택

> **요약** (기준일 2026-11-20)
>
> - 채택: AWS 서비스만 사용. 웹은 React·Vite·TypeScript를 S3·CloudFront로, API는 API Gateway HTTP API와 Lambda(Python 3.12), 저장은 DynamoDB, 자연어 질의는 Bedrock Claude Sonnet 5.5, 정의는 AWS SAM
> - 이유: 사용자 지시(AWS 아키텍처만 구성, Bedrock 모델 최대 Sonnet 5.5)와 질문 답변 4건(2026-11-20)
> - 역할: Frontend 웹 화면과 Lambda 코드는 이 저장소, 2D-3D 디지털트윈은 다른 팀원이 웹 임베드로 제공
>
> **다음 작업**: 첫 배포 후 Bedrock 호출 비용 실측(미정)

주: "AWS 서비스만 사용" 원칙은 [외부 판단 API JEV 운영 사용](2026-11-20%28%EC%99%B8%EB%B6%80%20%ED%8C%90%EB%8B%A8%20API%20JEV%20%EC%9A%B4%EC%98%81%20%EC%82%AC%EC%9A%A9%29.md)으로 일부 대체되었습니다(2026-11-20). 외부 API는 JEV 1개만 예외입니다.

[시스템 설계](../architecture.md) 2절의 기술 스택을 정한 기록입니다.

주: 2026-11-20 첫 배포에서 bedrock-mantle이 Sonnet 5.5 ID를 404로 거부해 호출 경로를 bedrock-runtime global 추론 프로필로 바꿨습니다. 변경 경위는 [장애 기록](../troubleshooting/2026-11-20%28Bedrock%20Sonnet%205.5%20%EB%AA%A8%EB%8D%B8%20ID%20404%29.md)에 있습니다.

## 1. 배경: AWS 전용 조건과 역할 분담

**1-1. 사용자는 아키텍처를 AWS로만 구성하고, 본인 역할을 Frontend 웹 화면과 Lambda 코드로 정했습니다(2026-11-20).**

2026-11-19 설계서의 권장안(FastAPI, PostgreSQL)은 서버 운영이 필요해 이 조건과 맞지 않았습니다.

## 2. 평가 대상: 질문 4건의 선택지

**2-1. Frontend 스택, Lambda 런타임, 리소스 정의 방식, 작업 범위를 선택지로 제시했습니다.**

| 항목 | 선택 | 탈락한 후보 |
|---|---|---|
| Frontend | React + Vite + TypeScript | Next.js 정적 export, Vue 3 |
| Lambda | Python 3.12 | Node.js 20 + TypeScript |
| 리소스 정의 | AWS SAM | AWS CDK, Terraform, 콘솔 수동 |
| 작업 범위 | 문서, 폴더, 첫 화면, Lambda 3개 | 문서·폴더만, MVP 전체 |

## 3. 측정 방법: 로컬 실행으로 동작 확인

**3-1. 배포 전이라 비용·지연은 측정하지 않았고, 로컬 테스트와 빌드로 동작만 확인했습니다.**

| 확인 | 결과 |
|---|---|
| Lambda 단위 테스트(`python3 -m unittest discover tests`) | 6건 통과 |
| SAM 템플릿 검사(`sam validate --lint`) | 통과 |
| Bedrock 클라이언트 import(anthropic 2.11.0, `AnthropicBedrockMantle`) | 통과, 호출은 미실행 |
| Frontend 빌드·lint | 통과, 경고 0건 |
| 화면 1440px·390px | 가로 넘침·라벨 잘림 없음(데모 모드) |

## 4. 후보: 데이터 저장소와 LLM

**4-1. 저장소는 DynamoDB, LLM은 Bedrock bedrock-mantle 엔드포인트의 Claude를 택했습니다.**

| 항목 | 선택 | 이유 |
|---|---|---|
| 저장소 | DynamoDB | 스케줄만 저장, 서버리스, 호실 목록은 코드 패키지 JSON |
| LLM 모델 | Claude Sonnet 5.5(`anthropic.claude-sonnet-5-5`) | 사용자 지시 "최대 Sonnet 5.5". 템플릿 `AllowedValues`로 Sonnet 5.5와 Haiku 5.5만 허용 |
| 리전 | ap-northeast-2(서울) | Claude in Amazon Bedrock 글로벌 엔드포인트 지원 리전 |
| IAM | `bedrock-mantle:CreateInference` | 모델 ARN 형식 미확인으로 `Resource: '*'`, 첫 배포 후 축소 |

## 5. 결과: 구현 파일

**5-1. `frontend/`와 `lambda/` 두 폴더에 첫 화면과 Lambda 3개를 만들었습니다.**

API는 `GET /rooms/status`, `POST /query`, `GET·POST /schedules` 3종입니다.

## 6. 결정

**6-1. 위 구성을 채택하고, 설비 데이터는 가상 데이터, 제어는 스케줄 저장과 시뮬레이션 반영까지로 제한합니다.**

## 7. 운영 시 주의

**7-1. Bedrock 모델 접근은 계정·리전별로 콘솔에서 확인해야 하며, 호출 비용은 첫 배포 후 실측합니다.**

- AWS 자격 증명은 `aws configure --profile maestro`로 각자 터미널에서 입력하고, 키를 대화·문서·저장소에 남기지 마십시오.
- `lambda/template.yaml`의 `ModelId`에 Opus 계열을 추가하지 마십시오.
