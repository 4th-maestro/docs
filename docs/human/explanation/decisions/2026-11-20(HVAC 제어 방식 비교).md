## 1. 배경: 강화학습 제외, 규칙 기반과 JEV 기반 2종 비교

**1-1. 사용자는 명세 3종(규칙 기반, DDPG, JEV) 중 DDPG를 제외하고 2종의 비교를 요청했습니다(2026-11-20).**

구현 전에 사용자에게 4건을 확인했습니다. 쾌적 범위 조건은 명세의 규칙 기반 재실 설정(냉방 26℃, 난방 20℃)이 쾌적 목표 24~26℃와 맞지 않아 질문했습니다.

**표 1.1 사용자 확인 결과(2026-11-20)**

| 항목 | 선택 | 탈락한 선택지 |
|---|---|---|
| 결과물 범위 | 구현과 실행까지 | 평가 설계 문서만 |

**1-2. 완성 아키텍처(2026-11-20)는 JEV를 5분 주기 빈 방·이상 판단에, DRL을 SageMaker Endpoint 최적 제어 추천에 배치합니다.**

이번 평가는 JEV가 15분마다 공간별 설정온도를 직접 선택하는 방식입니다. 완성 아키텍처의 JEV 역할(빈 방 판단 후 제어)과 주기·출력이 다릅니다. 결과는 6절에서 완성 아키텍처의 역할과 연결해 해석했습니다.

## 3. 측정 방법: 조정 1주와 분리된 평가 2주, 지표 4종

**3-1. 계절마다 조정 기간 1주에서 JEV 판단 기준을 조정하고, 분리된 평가 기간 2주에서 두 방식을 비교했습니다.**

두 방식은 같은 건물, 기상, 사용 일정, 초기 상태(공실 설정, 운전 모드 고정)로 실행했습니다. 기간마다 1회 실행했습니다. 연도 2026은 요일 계산에만 사용하고, 기상은 TMYx 대표 연도 값입니다.

**표 3.1 실행 기간**

| 계절 | 조정 기간 | 평가 기간 | 쾌적 범위(판정 범위) |
|---|---|---|---|
| 냉방 | 2026-07-13(월)~07-19, 7일 | 2026-08-03(월)~08-16, 14일 | 24~26℃(23.5~26.5℃) |
| 난방 | 2026-01-12(월)~01-18, 7일 | 2026-02-02(월)~02-15, 14일 | 20~22℃(19.5~22.5℃) |

**표 3.2 지표**

| 지표 | 계산 |

## 4. 후보: 규칙 기반과 JEV 기반, DDPG는 제외

**4-1. 두 방식은 같은 제어 제한을 따르며, JEV에만 OFF와 FAN 선택지가 있습니다.**

**표 4.1 후보 구성**

| 항목 | 규칙 기반 | JEV 기반 |
|---|---|---|
| 판단 | 재실 중이거나 사용 시작 30분 이내면 재실 설정, 아니면 공실 설정 | 공간마다 choice 질문 1개, 15분마다 요청 1회(질문 5개) |
| 운전 상태 | 냉방 또는 난방 고정, OFF 없음 | OFF, FAN, 냉방 또는 난방 |
| 설정온도 | 냉방 재실 26·공실 28℃, 난방 재실 20·공실 16℃ | 현재 설정 -1, 0, +1℃ 중 선택 |
| 설정 범위 | 위 4개 값 | 냉방 23~28℃, 난방 16~23℃ |
| 변경 제한 | 15분당 ±1℃ | 15분당 ±1℃ |
| 모델 | 없음 | `jev-latest`(1.14.0), TypeSafe 직접 호출 |
| API 실패 시 | 해당 없음 | 3회 재시도 후 그 15분은 규칙 기반으로 대체, 횟수 기록 |

주: 예제의 실내기 팬은 연속 운전입니다. OFF는 실내기 가용 스케줄 0, FAN은 코일을 정지하고 팬 운전과 외기 도입만 유지하는 방식으로 구현했습니다.

**4-2. JEV 입력은 명세 5개 그룹을 따르며, 단열 특성은 생략했습니다.**

| 그룹 | 입력 |
|---|---|
| 공간·설비 | 용도, 면적, 층고, 창 방위·면적, 외벽 여부, 실내기 용량 |
| 현재 상태 | 외기 온습도·일사, 실내 온습도, 재실 인원, 조명·장비 전력, 운전 상태, 설정온도, 실내기 출력, 건물 HVAC 전력 |
| 최근 이력 | 최근 60분 15분 간격 온도·운전 상태·설정온도, 온도 변화율, 마지막 설정 변경 후 경과 시간 |
| 예정 정보 | 다음 사용까지 남은 시간, 예상 인원, 사용 지속 시간 |
| 목표·제약 | 쾌적 범위, 허용 오차, 쾌적 우선 순위, 설정 범위, 변경 폭 |

| 후보 | 제외 이유 |

## 6. 결정: JEV 기반을 빈 방 판단 제어 후보로 유지, 규칙 기반은 대체 제어

**6-1. JEV 기반은 냉방 쾌적을 유지하면서 전력량을 감소시켰고, 절감 근거는 공실 구간 OFF 판단과 사용 전 재가동 시점 판단입니다.**

이 결과는 완성 아키텍처의 JEV 역할(빈 방 판단 후 제어)과 일치합니다. 규칙 기반은 외부 API 없이 동작하므로 API 장애 시 대체 제어로 유지하는 것을 권장합니다. 하네스는 API 실패 시 규칙 기반으로 대체하는 구조로 구현했습니다.

**6-2. 채택 확정은 보류합니다. 절감의 대부분이 OFF 선택지에서 나왔으므로 같은 선택지를 가진 규칙과 비교해야 합니다.**

**표 6.1 권장안과 대안**

| 안 | 구성 | 장점 | 확인 필요 |
|---|---|---|---|
| 권장 | JEV(빈 방·재가동 판단) + 규칙 기반(대체 제어) | 사용 전 재가동 시점을 상태로 판단, 냉방 이탈 0h | 공실 OFF 규칙 대비 추가 절감 여부, 최대 전력 증가 |
| 대안 A | 규칙 기반 + 공실 OFF(사용 N분 전 재가동) | 외부 API 없음, 비용 0 | 미측정. N값 고정으로 기상 변화 대응 한계 |
| 대안 B | DRL(SageMaker Endpoint, 완성 아키텍처) | 연속 설정온도 최적화 | 학습 환경·시간 필요, 이번 비교 범위 밖 |
