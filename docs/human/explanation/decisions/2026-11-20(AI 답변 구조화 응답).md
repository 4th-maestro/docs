# AI 답변 구조화 응답

> **요약** (기준일 2026-11-20)
>
> - 채택: AI 답변을 구조화 응답(`output_config.format`, 결론·근거·조치 3칸)으로 받고, 서버가 칸마다 첫 문장만 표시해 3문장 이하를 보장함
> - 이유: 프롬프트 지침만으로는 35문항 중 3~12건이 3문장을 초과함. 사용자가 구조화 응답, 초과 시 재작성, 기준 완화 중 구조화 응답을 선택
> - 함께 추가: 층을 말하지 않은 제어 요청의 전체 층 초안은 서버가 실행하지 않고 되묻게 함(7차 평가 q22)
>
> | 항목 | 지침만(5~6차, 3회) | 구조화 응답(8차) | 기준 |
> |---|---:|---:|---|
> | 3문장 초과 | 3, 8, 12건 | 0건 | 0건 |
> | 정답 | 35, 34, 35/35 | 35/35 | 정답 목록 일치 |
> | 단일 턴 응답 시간 중앙값 | 3.6~4.3초 | 4.2초 | 없음 |
> | 층 미지정 요청의 되묻기 전 조회 호출 | 0회 | 12회 중 7회 | 0회 |
>
> **다음 작업**: 없음(되묻기 전 조회 호출은 허용, 평가 기준 조정 Lambda #18)

## 1. 배경: 3문장 규칙 미준수

**1-1. 시스템 프롬프트의 "답변은 3문장 이하" 지침을 구체화해도 초과 건수가 실행마다 3~12건으로 줄지 않았습니다.**

측정 경위는 [AI 운영 도우미 도구 선택 평가](../research/ai-tool-eval.md) 5절과 8절에 있습니다. 운영자(40~50대, 하루 종일 사용)가 한 번에 읽는 답변 길이를 일정하게 유지하기 위한 결정입니다.

## 2. 평가 대상: 평가 세트 35문항

**2-1. 평가 세트는 `lambda/eval/questions.json`의 단일 턴 31문항과 다중 턴 4문항입니다.**

## 3. 측정 방법: 실제 Bedrock, JEV 판단, 문장 수 검사

**3-1. `lambda/tools/eval_ai.py`로 도구 선택을 정답과 비교하고, 답변은 JEV 판단과 문장 수 검사로 확인했습니다.**

문장 끝은 한글·닫는 괄호 뒤 마침표·물음표·느낌표입니다. 구조화 응답은 칸 사이 줄바꿈도 문장 경계로 셉니다.

## 4. 후보: 3가지

**4-1. 사용자에게 3가지 후보를 제시했고, 사용자는 구조화 응답을 선택했습니다.**

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 구조화 응답 | 3문장 보장, 화면 3줄 표시 | 스키마로 글자 수 제한 불가(`maxLength` API 미지원), Lambda·Frontend 변경 | 채택 |
| 초과 시 재작성 | 답변 형식 유지 | 해당 답변만 1~2초 추가, 긴 답변이 먼저 보였다가 교체 | 미채택 |
| 기준을 4문장으로 완화 | 코드 변경 없음 | 6차 기준 4문장 이하 33/35, 운영자 읽기 부담 유지 | 미채택 |

## 5. 결과: 3문장 초과 0건, 되묻기 전 조회 증가

**5-1. 구조화 응답에서 3문장 초과는 7차·8차 모두 0건이었습니다.**

| 실행 | 정답 | 3문장 초과 | 문장 수 분포 |
|---|---:|---:|---|
| 7차(구조화 응답) | 34/35 | 0 | 미기록 |
| 8차(구조화 응답 + 층 검증) | 35/35 | 0 | 1문장 1, 2문장 8, 3문장 26 |

- 7차의 오답 1건(q22)은 "진료실 설정온도 22도로 오후 3시부터"에 층을 되묻지 않고 전체 층 초안을 만든 경우입니다. 서버 검증(`query.floor_given`)을 추가해 범위(전체, 모든 층, 재실 0곳 등)를 말하지 않은 전체 층 초안은 실행하지 않고 되묻게 했습니다.
- 칸 1개에 여러 정보를 쉼표로 이어 쓰는 경향이 있어 문장 1개가 길어졌습니다. 글자 수는 제한하지 않았습니다.

**5-2. 층 미지정 제어 요청 12회 중 7회는 되묻기 전에 조회 도구를 먼저 호출했습니다.**

층 추정 초안은 0회였고, 서버 검증이 거부한 경우도 0회였습니다. 조회 후 답변은 모두 층을 되물었고, 왕복이 1회(약 1~2초) 늘었습니다. "되묻기 전 조회 금지" 지침을 추가하자 q22 조회가 5회 중 5회로 늘어 지침은 되돌렸습니다.

## 6. 결정: 구조화 응답, 칸마다 첫 문장

**6-1. 서버는 부분 JSON을 읽어 칸 텍스트만 화면에 스트리밍하므로, 화면은 기존 글자 단위 표시와 같은 방식으로 3줄을 표시합니다.**

| 위치 | 내용 |
|---|---|
| `lambda/src/query.py` `ANSWER_FORMAT` | `conclusion`(결론, 되묻기는 질문), `detail`(근거, 되묻기는 후보), `action`(다음 조치, 되묻기·인사는 빈 값) |
| `lambda/src/query.py` `render` | 칸마다 첫 문장, 줄바꿈 연결. 스트리밍 중 이미 보낸 앞부분은 바뀌지 않음(단위 테스트) |
| `frontend/src/ai/chat.css` `.msg-text` | 줄바꿈 유지, 한글 단어 중간 줄바꿈 방지(Frontend #12) |

## 7. 운영 시 주의: 칸 순서, 조회 호출

**7-1. 모델이 칸 순서를 바꾸면 스트리밍 표시를 멈추고 완료 시 전체 답변으로 교체합니다.**

- 되묻기 전 조회 호출은 모델 호출 1회를 추가하므로 질의당 입력 토큰이 약 4,000 증가합니다(문항당 평균 입력 기준 추정). 사용자 결정(2026-11-20)으로 허용하고, 평가는 초안을 만들지 않으면 정답으로 채점합니다.
- 구조화 응답 실패(거부, 토큰 한도)로 JSON이 없으면 "응답을 만들지 못했습니다."를 표시합니다.
