# 고객사 관리자 호실 이름·용도 변경 허용

> **요약** (기준일 2026-11-21)
>
> - 채택: 고객사 관리자(`manager`)와 판매사 관리자만 운영 탭 호실 상세 카드에서 호실 이름과 용도를 변경함. 운영자(`operator`)는 조회만 하고, 그 밖의 고객사 변경은 계속 403임
> - 이유: 사용자 지시(2026-11-21) "고객사측도 3D 디지털 트윈의 각 방에 이름과 용도는 설정할 수 있도록". [판매사 건물 관리와 고객사 관제 전용](2026-11-20%28%ED%8C%90%EB%A7%A4%EC%82%AC%20%EA%B1%B4%EB%AC%BC%20%EA%B4%80%EB%A6%AC%EC%99%80%20%EA%B3%A0%EA%B0%9D%EC%82%AC%20%EA%B4%80%EC%A0%9C%20%EC%A0%84%EC%9A%A9%29.md)의 고객사 변경 차단 중 호실 이름·용도만 예외로 둠
> - 구현: Lambda #68(`PATCH /buildings/{id}/rooms/{roomId}`), Frontend #72(호실 상세 카드), `dev` 머지
>
> | 결정 항목 | 선택 | 다른 선택지 |
> |---|---|---|
> | 변경 가능 역할 | 고객사 관리자, 판매사 관리자 | 고객사 구성원 전체 |
> | 화면 위치 | 운영 탭 호실 상세 카드 | 설정 화면 호실 목록 표, 둘 다 |
> | 용도 입력 | 트윈 계산 용도 9종 중 선택 | 자유 입력 |
> | 트윈 도면이 없는 건물 | 허용(호실 테이블만 갱신) | 트윈 건물만 허용 |
> | 저장 후 3D 반영 | 트윈 화면 다시 열기(약 1~2초) | 트윈에 변경 메시지 전달 |
>
> **다음 작업**: `main` 반영과 배포 후 고객사 관리자, 운영자 계정으로 버튼 표시와 저장 확인

## 1. 배경: 고객사 호실 정보 수정 요구

**1-1. 호실 이름과 용도는 고객사가 가장 잘 아는 정보이며, 용도는 냉방 부하와 재실 추정 계산에 쓰입니다.**

2026-11-20 결정으로 고객사 계정의 모든 변경 요청은 403으로 차단됐습니다. 호실 이름이나 용도가 바뀔 때마다 판매사에 요청해야 했습니다.

## 2. 평가 대상: 권한 범위와 저장 방식

**2-1. 사용자가 권한, 화면, 용도 입력, 트윈 없는 건물, 3D 반영 방식 5가지를 직접 골랐습니다.**

요약 표의 "선택" 열이 사용자 선택이며, 각 항목에서 권장안이 채택됐습니다.

## 3. 측정 방법: 단위 테스트와 화면 확인

**3-1. Lambda 단위 테스트와 임시 테스트 화면으로 확인했습니다.**

- Lambda: 고객사 관리자 성공(트윈 새 버전, 호실 테이블, 상태 API, 변경 이력), 운영자 403, 다른 기업 403, 잘못된 용도 400, 41자 이름 400, 없는 호실 404, 중지 기업 403, 트윈 없는 건물
- 화면: 1440px, 390px, 밝은 화면, 어두운 화면에서 입력칸 48px, 저장·취소 같은 크기, 라벨 잘림 없음

## 4. 결정: 호실 이름·용도만 예외 허용

**4-1. 저장은 판매사 저장과 같은 방식(트윈 `building.json` 새 버전, 호실 테이블, 변경 이력 `room.update`)입니다.**

트윈 `use`에는 용도 키를, 호실 테이블 `use`에는 한국어 이름을 저장합니다. 재실 규칙(`sim.py`)이 한국어 이름으로 비교하기 때문입니다. 같은 건물의 두 호실을 동시에 저장하면 `building.json`에는 마지막 저장만 남습니다(코드에 `shortcut:` 주석).
