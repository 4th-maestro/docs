# 규정 문서 RAG 벡터 저장소

> **요약** (기준일 2026-11-20)
>
> - 채택: Bedrock Knowledge Base + S3 Vectors + Titan Text Embeddings V2. 기존 Lambda 도구 루프에서 Retrieve API로 조회(Bedrock Agent 전환 안 함)
> - 이유: 문서 7건 규모에서 S3 Vectors는 사용량 과금이라 월 비용이 1센트 미만. OpenSearch Serverless는 최소 월 약 214~428달러, Aurora pgvector는 최소 월 약 73달러
> - 결과: 배포 후 수집 7건 성공(14.5초), Retrieve 중앙값 0.345초, 배포된 질의 Lambda가 고시 제14조와 시행일을 근거로 답변
>
> | 항목 | 값 | 비교 기준 |
> |---|---|---|
> | S3 Vectors 저장 | GB·월 0.066달러 | OpenSearch Serverless OCU 시간당 0.293달러 |
> | S3 Vectors 조회 | 1,000회 0.0027달러 | 질의 1건당 Retrieve 1회 |
> | Titan Text Embeddings V2 | 1,000토큰 0.0000246달러 | 문서 7건 약 1.9만 자 |
> | Retrieve 응답 시간 | 중앙값 0.345초, 최대 0.405초(10회) | 질의 Lambda 제한 30초 |
>
> **다음 작업**: 고시 개정 시 KB 문서 갱신, 검색 결과 수 부족 질의 점검(미정)

[요구사항](../../reference/requirements.md) FR-18을 구현하기 전에 벡터 저장소, 임베딩 모델, 호출 방식을 정한 기록입니다. 수록 문서의 원문 확인은 [KB 수록 자료 조사](../research/kb-sources.md)에 있습니다.

## 1. 배경: FR-18 비용 점검 보류와 문서·데이터 분리 구성안

**1-1. FR-18은 "벡터 저장소 비용 점검 후"로 보류된 상태였고, 사용자는 2026-11-20 문서·데이터 분리 구성안을 제시했습니다.**

구성안은 규정·쾌적 이론 문서를 Knowledge Base에, 센서·전력 수치를 도구 조회에, 불쾌지수·PMV 공식을 Lambda 계산에 두는 방식입니다. 사용자는 질문 3건에 다음과 같이 답했습니다.

| 질문 | 선택 | 탈락한 선택지 |
|---|---|---|
| 진행 범위 | 원문 확인 + KB 구현까지 | 원문 확인과 설계 기록만, 계산 도구만 먼저 |
| 도구 호출 방식 | 현재 Lambda 도구 루프 유지 | Bedrock Agent 전환 |
| 출처 표시 | 답변 아래 근거 목록 화면 추가 | Lambda 응답만 추가, 답변 문장에 포함 |

## 2. 평가 대상: 규정·쾌적 기준 문서 7건

**2-1. 원문 또는 공개 라이선스로 확인한 문서 7건(약 1.9만 자)을 대상으로 했습니다.**

법령·고시 원문 3건과 자체 요약 4건입니다. 문서 목록과 수록 근거는 [KB 수록 자료 조사](../research/kb-sources.md) 10절에 있습니다. 문서마다 `.md.metadata.json`에 문서명, 원문 주소, 시행일, 원문 확인일을 넣었습니다.

## 3. 측정 방법: Seoul 단가 조회, 리전 지원 확인, 배포 후 실측

**3-1. 단가는 AWS Pricing API, 지원 여부는 Seoul 리전 API·CloudFormation 스키마 조회로 확인했습니다(2026-11-20).**

| 확인 | 방법 | 결과 |
|---|---|---|
| 임베딩 모델 | `bedrock list-foundation-models --by-output-modality EMBEDDING` | Titan Text Embeddings V2(온디맨드), Cohere Embed v4(추론 프로필) |
| S3 Vectors, KB API | `s3vectors list-vector-buckets`, `bedrock-agent list-knowledge-bases` | Seoul에서 호출 가능 |
| CloudFormation | `AWS::Bedrock::KnowledgeBase` 스키마 | 저장 유형 `S3_VECTORS`, `S3VectorsConfiguration` 지원 |
| 단가 | `pricing get-products`(AmazonS3, AmazonES, AmazonRDS, AmazonBedrock) | 4절 표 |

배포 후에는 수집 작업 결과, Retrieve 10회 응답 시간, 배포된 질의 Lambda 직접 호출 2건을 확인했습니다.

## 4. 후보: 벡터 저장소 3종, 임베딩 2종

**4-1. 문서가 수십 건 규모라 고정 최소 비용이 없는 저장소가 유리합니다.**

**표 4.1 벡터 저장소 후보(Seoul)**

| 후보 | 단가 | 최소 월 비용 | 판단 |
|---|---|---|---|
| S3 Vectors | 저장 GB·월 0.066달러, 조회 1,000회 0.0027달러, PUT GB 0.219달러 | 없음(사용량 과금) | 채택 |
| OpenSearch Serverless | OCU 시간당 0.293달러 | 약 214달러(비중복 1 OCU)~428달러(2 OCU) | 탈락: 고정 비용 |
| Aurora PostgreSQL Serverless v2(pgvector) | ACU 시간당 0.20달러 | 약 73달러(0.5 ACU). 0 ACU 자동 일시정지는 재개 지연 | 탈락: 고정 비용, 재개 지연 |

주: 외부 벡터 DB(Pinecone, MongoDB Atlas)는 AWS 전용 원칙으로 제외했습니다. 월 비용은 730시간 기준 계산값입니다.

**표 4.2 임베딩 모델 후보**

| 후보 | Seoul 단가 | 판단 |
|---|---|---|
| Titan Text Embeddings V2(1024차원) | 1,000토큰 0.0000246달러, 온디맨드 | 채택: 한국어 지원, 온디맨드 |
| Cohere Embed v4 | Pricing API에서 Seoul 항목 미확인 | 탈락: 단가 미확인, 추론 프로필 필요 |

## 5. 결과: 수집 7건 성공, 근거 인용 답변 확인

**5-1. 배포 후 수집과 검색이 정상 동작했습니다.**

| 확인 | 결과 |
|---|---|
| 수집 작업(`tools/kb_sync.sh`) | 신규 7건, 실패 0건, 14.5초 |
| Retrieve "공공기관 냉방 기준 온도" | 상위 4건: 기준 비교, 고시 제14조, 설계기준, 제한온도 제도 |
| Retrieve 응답 시간 | 10회 중앙값 0.345초, 최대 0.405초(로컬 CLI 측정) |
| 배포된 질의 Lambda "공공기관 냉방 기준 온도는?" | 고시 제14조와 시행일 2026-04-30을 인용, `sources` 4건 |
| 배포된 질의 Lambda "불쾌지수가 가장 높은 곳 3곳" | `comfort_index` 호출, 막대 그래프 1개 |
| 도구 선택 평가(`tools/eval_ai.py`) | 기존 35/35, 신규 4/4(규정 2, 쾌적 지표 2) 정답. 신규 4건 입력 43,030토큰 |

**5-2. 일부 질의는 요청한 4건보다 적은 결과를 반환했습니다.**

"불쾌지수 단계 기준"과 "PMV 정의"는 1건, "사무소 설계용 실내 습도"는 2건이었습니다. 첫 결과는 모두 해당 주제 문서였습니다. 원인은 확인하지 않았습니다.

## 6. 결정: S3 Vectors와 Titan V2, Retrieve API 도구

**6-1. 비용과 기존 구조 유지를 기준으로 S3 Vectors, Titan Text Embeddings V2, Lambda 도구 `search_documents`를 선택했습니다.**

질의 Lambda는 KB를 Retrieve API로 조회하고, 결과의 문서명·시행일·원문 주소를 응답 `sources`로 돌려줍니다. 계산 공식은 `comfort_index` 도구(`lambda/src/comfort.py`)가 담당합니다. 문서 수가 수천 건 이상으로 늘거나 하이브리드 검색이 필요하면 OpenSearch Serverless를 다시 검토합니다.

## 7. 운영 시 주의: 문서 갱신과 검색 결과 수

**7-1. 다음 조건에서 재확인이 필요합니다.**

| 항목 | 주의 |
|---|---|
| 고시 개정 | 공공기관 규정, 설계기준이 바뀌면 `lambda/kb/` 문서와 시행일 메타데이터를 고친 뒤 `tools/kb_sync.sh` 실행 |
| 결과 수 부족 | 5-2절의 1~2건 반환 원인 미확인. 청크 크기(300토큰)와 결과 수 설정 점검 필요 |
| 메타데이터 크기 | 필터 가능 메타데이터 한도 때문에 `AMAZON_BEDROCK_TEXT`, `AMAZON_BEDROCK_METADATA`를 필터 제외 키로 지정 |
| 비용 실측 | 수집·조회 비용은 단가 기준 추정. 청구서 실측 미확인 |
